# Конфигурация

Kachō API Gateway конфигурируется через переменные окружения. Большинство — с префиксом
**`KACHO_API_GATEWAY_`**; ключи AuthN-инфраструктуры (Hydra / JWKS / DPoP) — с префиксом
`KACHO_` (общие для платформы). Эта страница перечисляет ключевые группы и даёт пример.

:::warning Secure-by-default
При `KACHO_APP_ENV=production` гейтвей **откажется стартовать**, если authz выключен
(`AUTHZ_ENABLED=false`), включён fail-open (`AUTHZ_FAIL_OPEN=true`), AuthN не в production-режиме
или internal gRPC-listener не защищён mTLS. Пустой/неустановленный `KACHO_APP_ENV` (дефолт)
пропускает гейт — dev-режим для локальных стендов.
:::

Церемонию интерактивного входа проводит консоль входа развёрнутого провайдера личности —
край её не настраивает и своих ключей под неё не принимает. Прежние ключи
`KACHO_API_GATEWAY_OIDC_*` сняты с контракта: их не объявлял ни один профиль, а маршруты,
которые они питали, адресовали снятого провайдера. Имена зарезервированы и не
переиспользуются. Детали проверки предъявителя — [Аутентификация](/architecture/authn).

## Проекция потока изменений (подписка)

Ручка `GET /subscription/v1/events` — единственная проекция подписки на изменения
(см. [Подписку на изменения](/api/subscription)). Умолчаний у величин посадки нет там, где
умолчание было бы решением за оператора.

<table>
  <thead><tr><th>Переменная</th><th>По умолчанию</th><th>Описание</th></tr></thead>

`501` с текстом `no journal owner is declared for this edge` — владелец не назван профилем.
`400` `unknown owner` — назван не тот, кого объявила эта посадка. `501` от владельца — домен
объявлен, но глагола не служит. Самоотчёт процесса при старте называет число владельцев и их
имена: ноль — законное состояние, но оно обязано быть видно.
:::

## Собственного internal gRPC-listener'а у края нет

Здесь стоял раздел с ручками отдельного cluster-internal gRPC-listener'а края — его адресом,
включением mTLS, серверной парой и списком законных отправителей. Ни одной из этих переменных
**больше не существует**: listener снят вместе с единственной службой, которую он подавал
(сброс authz-кэша по вызову от `kaname`). Выставленная в профиле, любая из них сегодня
ничего не настраивает.

Урок, ради которого раздел не удалён молча, стоит сохранить: там же объяснялось, почему у
gRPC server-reflection **нет собственной ручки** — переключатель, чьё безопасное значение всегда
совпадает с посадкой, либо избыточен, либо однажды будет выставлен так, что откроет перечисление
схемы на порту, который никого не авторизует. Правило остаётся; его прежний предмет — нет.

Кэш решений край гасит сам, читая журнал смены субъекта у `kaname`
(`KACHO_API_GATEWAY_SUBJECT_CHANGE_POLL_INTERVAL` выше) — см.
[Авторизация](/architecture/authz).

## Пример YAML

<CodeBlock language="yaml" title="api-gateway.env.yaml">
  {dedent`
    KACHO_APP_ENV: production

    KACHO_API_GATEWAY_LISTEN_ADDR: ":8080"
    KACHO_API_GATEWAY_TLS_LISTEN_ADDR: ":443"
    KACHO_API_GATEWAY_TLS_CERT_FILE: /tls/tls.crt
    KACHO_API_GATEWAY_TLS_KEY_FILE: /tls/tls.key

    # AuthN — production Hydra + DPoP
    KACHO_API_GATEWAY_AUTHN_MODE: production-strict
    # Посадка личности: чем стенд проверяет ЧЕЛОВЕКА — внешним поставщиком
    # удостоверений (external) или собственной чеканкой платформы (own).
    # Умолчания НЕТ: незаданное и неизвестное значение — отказ старта.
    # На крае поле разводит ДВА требования, и второе — ЗАМЕЩЕНИЕ, а не
    # послабление:
    #   · АДМИНИСТРАТИВНЫЙ адрес поставщика (им выход человека снимает сессию на
    #     его стороне) — обязателен под external, под own снимается: такой
    #     сессии не существует;
    #   · КТО ОТВЕЧАЕТ ОБ ОТЗЫВЕ на предъявлении — под external поставщик
    #     (KACHO_HYDRA_INTROSPECTION_URL), под own НАШ авторитет
    #     (KACHO_API_GATEWAY_PLATFORM_TOKEN_REVOCATION_URL) вместе с якорем
    #     доверия и КЛИЕНТСКОЙ ПАРОЙ: авторитет спрашивает сертификат, и хопу
    #     без пары он откажет на каждом запросе.
    # Читать отзыв обязана ЛЮБАЯ полоса: отзыв, действующий на выдаче и не
    # действующий на предъявлении, отзывом не является. Значение обязано
    # СОВПАДАТЬ с тем, что объявила служба прав, — половины одного стенда не
    # решают о личности по-разному.
    KACHO_API_GATEWAY_IDENTITY_PROVIDER: external
    KACHO_API_GATEWAY_AUTHN_ENABLE_DPOP: "true"
    # Издатель — МНОЖЕСТВО: платформа чеканит свои токены сама, прежний издатель
    # на переходе остаётся, и у каждого СВОЯ запись источника ключей. Один набор
    # на двоих означал бы, что ключ одного проверяет токен другого.
    KACHO_API_GATEWAY_TOKEN_ISSUERS: "https://iam.kacho.local,https://auth.kacho.cloud"
