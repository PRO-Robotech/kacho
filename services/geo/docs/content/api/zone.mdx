# Zone

**Zone** — зона доступности внутри региона ([Region](/api/region)): часть топологии, в которой
размещаются нагрузки. Несёт `status` (UP / DOWN), отражающий доступность зоны. Как и регион,
Zone — глобальный cluster-scoped read-only справочник (не принадлежит проекту). Consumer-сервисы
(Compute, VPC) ссылаются на зону по `zoneId` и валидируют её через `ZoneService.Get`.

Идентификатор зоны **назначается администратором** (`ru-central1-a`) и **неизменяем** (immutable
PK). Зона привязана к региону полем `regionId` — внешний ключ на `Region.id` с
`ON DELETE RESTRICT`.

Идентичность у зоны, как и у региона, **одна** — этот идентификатор: слаг пишет человек, и он
читаем сам по себе. Поле `name` снято из контракта задачей
[#716](https://github.com/PRO-Robotech/kacho/issues/716) вместе с местом, где два написания
одного и того же расходились; его номер и имя зарезервированы. Ключ `name` в теле запроса
край **молча отбросит** — см. предупреждение на странице [Region](/api/region).

## Методы

Чтение (`Get` / `List`) — публичное, на listener `:9090`. Администрирование
(`Create` / `Update` / `Delete`) — `InternalZoneService` на cluster-internal listener `:9091`,
синхронное (catalog-паттерн).

### Get — получить зону

<ApiOperation method="GET" endpoint="/geo/v1/zones/{id}">

Возвращает зону по идентификатору. Публичное чтение — персонального гранта не нужно: отношение `viewer` на кластере платформа выдаёт
**системной выдачей** субъекту «любой аутентифицированный». **Аутентификация
обязательна.**

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/zones/ru-central1-a' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "region-1-a",
      "regionId": "region-1",
      "status": "UP",
      "createdAt": "2026-06-24T10:00:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### List — список зон

<ApiOperation method="GET" endpoint="/geo/v1/zones">

Возвращает список зон с cursor-пагинацией. Публичный read.

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/zones?pageSize=50' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "zones": [
        { "id": "ru-central1-a", "regionId": "ru-central1", "status": "UP", "createdAt": "2026-06-24T10:00:00Z" },
        { "id": "ru-central1-b", "regionId": "ru-central1", "status": "UP", "createdAt": "2026-06-24T10:00:00Z" }
      ],
      "nextPageToken": ""
    }
  `}
</CodeBlock>

</ApiOperation>

### Create — создать зону (admin, internal)

<ApiOperation method="POST" endpoint="/geo/v1/internal/zones">

Создаёт зону с **явно заданным** id, привязанную к существующему региону (`regionId`).
Синхронная internal-операция (требует `system_admin`).

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:19091/geo/v1/internal/zones' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{
            "id": "ru-central1-c",
            "regionId": "ru-central1",
            "status": "UP"
          }'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "ru-central1-c",
      "regionId": "ru-central1",
      "status": "UP",
      "createdAt": "2026-06-24T10:10:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### Update — изменить зону (admin, internal)

<ApiOperation method="PATCH" endpoint="/geo/v1/internal/zones/{id}">

Меняет изменяемые поля зоны — `status` и блок `infra` (последний живёт только на админской
проекции). Привязку к региону (`regionId`) изменить нельзя — она immutable, и **переименовать
зону нечем**: имени у неё нет. Синхронная internal-операция.

<CodeBlock language="bash">
  {dedent`
    # перевести зону в DOWN
    curl -X PATCH 'http://localhost:19091/geo/v1/internal/zones/ru-central1-c' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "status": "DOWN" }'
  `}
</CodeBlock>

:::note Частичное обновление status
Если в запросе `Update` поле `status` не передано (или передано как `STATUS_UNSPECIFIED`),
текущий статус зоны **не меняется** — обновляются только явно заданные поля. Это позволяет
править блок `infra`, не трогая доступность зоны.
:::

</ApiOperation>

### Delete — удалить зону (admin, internal)

<ApiOperation method="DELETE" endpoint="/geo/v1/internal/zones/{id}">

Удаляет зону. Синхронная internal-операция. Удаление зоны разблокирует удаление её региона
(если она была последней привязанной зоной).

<CodeBlock language="bash">
  {dedent`
    curl -X DELETE 'http://localhost:19091/geo/v1/internal/zones/ru-central1-c' \\
      -H 'Authorization: Bearer <admin-JWT>'
  `}
</CodeBlock>

</ApiOperation>

## Ошибки и граничные случаи

<table>
  <thead><tr><th>Ситуация</th><th>Код</th><th>Поведение</th></tr></thead>
  <tbody>
    <tr><td>Get/Delete несуществующей зоны</td><td><code>NOT_FOUND</code></td><td><code>"Zone &lt;id&gt; not found"</code></td></tr>
    <tr><td>Create с уже занятым id</td><td><code>ALREADY_EXISTS</code></td><td><code>"Zone &lt;id&gt; already exists"</code> — PK-конфликт по <code>id</code></td></tr>
    <tr><td>Create с <code>regionId</code> несуществующего региона</td><td><code>FAILED_PRECONDITION</code></td><td>Нарушение FK <code>regionId → Region.id</code></td></tr>
    <tr><td>Попытка изменить <code>regionId</code></td><td>—</td><td><code>regionId</code> immutable (FK-привязка задаётся при Create)</td></tr>
    <tr><td>Update без <code>status</code></td><td>—</td><td>Статус не меняется — частичное обновление (см. выше)</td></tr>
    <tr><td>Read без аутентификации</td><td><code>UNAUTHENTICATED</code></td><td>Чтение каталога грант не требует, но требует валидного принципала</td></tr>
    <tr><td>admin CRUD без <code>system_admin</code></td><td><code>PERMISSION_DENIED</code></td><td>Authz-Check не прошёл</td></tr>
  </tbody>
</table>

:::warning Internal-поверхность
`Create` / `Update` / `Delete` обслуживаются `InternalZoneService` на cluster-internal listener
(`:9091`) и **не публикуются** на external endpoint.
:::
