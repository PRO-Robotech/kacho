# Region

**Region** — верхнеуровневый элемент топологии платформы Kachō: географический регион, внутри
которого живут зоны доступности ([Zone](/api/zone)). Это глобальный cluster-scoped read-only
справочник: регион **не принадлежит** проекту или аккаунту, он описывает саму инфраструктуру.
Consumer-сервисы (Compute, VPC и др.) ссылаются на регион по id и валидируют его через
`RegionService.Get`.

Идентификатор региона **назначается администратором** явно (`ru-central1`) и **неизменяем**
после создания (immutable PK). Наполняет справочник администратор через `InternalRegionService`
(cluster-internal); публичный API только читает.

Идентичность у региона **одна** — этот идентификатор. Отдельного человекочитаемого имени у
региона нет: слаг пишет человек, и он читаем сам по себе, а второе поле того же назначения
давало только место, где два написания расходятся. Поле `name` снято из контракта задачей
[#716](https://github.com/PRO-Robotech/kacho/issues/716); его номер и имя зарезервированы.

:::warning Ключ `name` в теле запроса не ошибка, а НИЧТО
Край разбирает тело в сообщение запроса и **молча отбрасывает** ключи, которых в сообщении
нет (общее свойство всех методов платформы, не особенность geo). Поэтому `POST` с
`{"id": "...", "name": "..."}` ответит **успехом**, а имя просто никуда не попадёт — ошибки
вы не увидите. Единственный способ получить явный отказ — назвать поле в `updateMask`:
`PATCH` с `{"updateMask": "name"}` отвечает `400 INVALID_ARGUMENT`, потому что набор
изменяемых полей закрыт и `name` в него не входит.
:::

## Методы

Чтение (`Get` / `List`) — публичные, на listener `:9090`. Администрирование
(`Create` / `Update` / `Delete`) — `InternalRegionService` на cluster-internal listener
`:9091`, синхронное (catalog-паттерн, возвращает ресурс, не `Operation`).

### Get — получить регион

<ApiOperation method="GET" endpoint="/geo/v1/regions/{id}">

Возвращает регион по идентификатору. Публичное чтение: персонального гранта не
нужно — отношение `viewer` на кластере платформа выдаёт **системной выдачей**
субъекту «любой аутентифицированный». **Аутентификация обязательна.**

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/regions/ru-central1' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "ru-central1",
      "createdAt": "2026-06-24T10:00:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### List — список регионов

<ApiOperation method="GET" endpoint="/geo/v1/regions">

Возвращает список регионов с cursor-пагинацией (`pageSize`, `pageToken` → `nextPageToken`).
Публичный read.

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/regions?pageSize=50' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "regions": [
        { "id": "ru-central1", "createdAt": "2026-06-24T10:00:00Z" }
      ],
      "nextPageToken": ""
    }
  `}
</CodeBlock>

</ApiOperation>

### Create — создать регион (admin, internal)

<ApiOperation method="POST" endpoint="/geo/v1/internal/regions">

Создаёт регион с **явно заданным** администратором id. Синхронная операция: ответ — сам
ресурс. Доступна только на cluster-internal listener (`InternalRegionService`, требует
отношение `system_admin`).

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:19091/geo/v1/internal/regions' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "id": "ru-central2" }'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "ru-central2",
      "createdAt": "2026-06-24T10:10:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### Update — изменить регион (admin, internal)

<ApiOperation method="PATCH" endpoint="/geo/v1/internal/regions/{id}">

Меняет изменяемые поля региона — `countryCode` и `status` (последний живёт только на админской
проекции). Идентификатор изменить нельзя (immutable PK), а **переименовать регион нечем**:
имени у него нет, идентификатор и есть имя. Синхронная internal-операция.

<CodeBlock language="bash">
  {dedent`
    curl -X PATCH 'http://localhost:19091/geo/v1/internal/regions/ru-central2' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "countryCode": "RU" }'
  `}
</CodeBlock>

</ApiOperation>

### Delete — удалить регион (admin, internal)

<ApiOperation method="DELETE" endpoint="/geo/v1/internal/regions/{id}">

Удаляет регион. Если к региону привязана хотя бы одна [Zone](/api/zone), удаление блокируется
(`FAILED_PRECONDITION`) внешним ключом `ON DELETE RESTRICT` — сначала удаляются зоны.
Синхронная internal-операция.

<CodeBlock language="bash">
  {dedent`
    curl -X DELETE 'http://localhost:19091/geo/v1/internal/regions/ru-central2' \\
      -H 'Authorization: Bearer <admin-JWT>'
  `}
</CodeBlock>

</ApiOperation>

## Ошибки и граничные случаи

<table>
  <thead><tr><th>Ситуация</th><th>Код</th><th>Поведение</th></tr></thead>
  <tbody>
    <tr><td>Get/Delete несуществующего региона</td><td><code>NOT_FOUND</code></td><td><code>"Region &lt;id&gt; not found"</code></td></tr>
    <tr><td>Create с уже занятым id</td><td><code>ALREADY_EXISTS</code></td><td><code>"Region &lt;id&gt; already exists"</code> — PK-конфликт по <code>id</code></td></tr>
    <tr><td><strong>Delete региона, к которому привязаны зоны</strong></td><td><code>FAILED_PRECONDITION</code></td><td>FK <code>Zone.regionId → Region.id ON DELETE RESTRICT</code> блокирует удаление; сначала удалить зоны</td></tr>
    <tr><td>Попытка изменить <code>id</code></td><td>—</td><td><code>id</code> — immutable PK; задаётся только при Create, не меняется</td></tr>
    <tr><td>Read без аутентификации</td><td><code>UNAUTHENTICATED</code></td><td>Чтение каталога грант не требует, но требует валидного принципала</td></tr>
    <tr><td>admin CRUD без <code>system_admin</code></td><td><code>PERMISSION_DENIED</code></td><td>Authz-Check не прошёл</td></tr>
  </tbody>
</table>

:::warning Internal-поверхность
`Create` / `Update` / `Delete` обслуживаются `InternalRegionService` на cluster-internal
listener (`:9091`) и **не публикуются** на external endpoint. Их REST-проекция доступна только
на internal mux `api-gateway`.
:::
