# Region

**Region** — верхнеуровневый элемент топологии платформы Kachō: географический регион, внутри
которого живут зоны доступности ([Zone](/api/zone)). Это глобальный cluster-scoped
справочник: регион **не принадлежит** проекту или аккаунту, он описывает саму инфраструктуру.
Consumer-сервисы (Compute, VPC и др.) ссылаются на регион по id и валидируют его через
`RegionService.Get`.

Идентификатор региона **назначается администратором** явно (`ru-central1`) и **неизменяем**
после создания (immutable PK). Наполняет справочник администратор кластера (право
`system_admin`) — публичными глаголами `RegionService` ниже либо, вместе с инфраструктурным
блоком, через `InternalRegionService` на cluster-internal listener.

Идентичность у региона **одна** — этот идентификатор. Отдельного человекочитаемого имени у
региона нет: слаг пишет человек, и он читаем сам по себе, а второе поле того же назначения
давало только место, где два написания расходятся. Поле `name` снято из контракта задачей
[#716](https://github.com/PRO-Robotech/kacho/issues/716); его номер и имя зарезервированы.

:::warning Ключ `name` в теле запроса не ошибка, а НИЧТО
Край разбирает тело в сообщение запроса и **молча отбрасывает** ключи, которых в сообщении
нет (общее свойство всех методов платформы, не особенность geo). Поэтому `POST` с
`{"id": "...", "name": "..."}` ответит **успехом**, а имя просто никуда не попадёт — ошибки
вы не увидите. Единственный способ получить явный отказ — назвать поле в `updateMask`:
`PATCH` с `{"updateMask": "name"}` отвечает `400 INVALID_ARGUMENT`, потому что набор
изменяемых полей закрыт и `name` в него не входит.
:::

## Методы

Чтение (`Get` / `List`) и администрирование (`Create` / `Update` / `Delete`) — публичный
`RegionService` на listener `:9090`. Мутации возвращают `Operation`, уже завершённую в самом
ответе (`done = true`; `response` — публичный Region, у удаления — `Empty`; отказ хранилища — в
`error`). Публичный вход инфраструктурного блока не несёт: регион, созданный здесь, получает
`numericInfraId = 0` («не назначен»), а поскольку поле неизменяемо после создания, назначить его
можно только внутренним созданием (`InternalRegionService`, cluster-internal `:9091`).

### Get — получить регион

<ApiOperation method="GET" endpoint="/geo/v1/regions/{id}">

Возвращает регион по идентификатору. Публичное чтение: персонального гранта не
нужно — отношение `viewer` на кластере платформа выдаёт **системной выдачей**
субъекту «любой аутентифицированный». **Аутентификация обязательна.**

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/regions/ru-central1' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "ru-central1",
      "createdAt": "2026-06-24T10:00:00Z"
    }
  `}
</CodeBlock>

</ApiOperation>

### List — список регионов

<ApiOperation method="GET" endpoint="/geo/v1/regions">

Возвращает список регионов с cursor-пагинацией (`pageSize`, `pageToken` → `nextPageToken`).
Публичный read.

<CodeBlock language="bash">
  {dedent`
    curl 'http://localhost:18080/geo/v1/regions?pageSize=50' \\
      -H 'Authorization: Bearer <JWT>'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "regions": [
        { "id": "ru-central1", "createdAt": "2026-06-24T10:00:00Z" }
      ],
      "nextPageToken": ""
    }
  `}
</CodeBlock>

</ApiOperation>

### Create — создать регион (admin)

<ApiOperation method="POST" endpoint="/geo/v1/regions">

Создаёт регион с **явно заданным** администратором id. Требует отношение `system_admin` на
кластере. Тело — `id`, `countryCode`, `status`; без `status` регион создаётся закрытым для
размещения (`DOWN`), и `metadata.warnings` об этом говорит.

<CodeBlock language="bash">
  {dedent`
    curl -X POST 'http://localhost:18080/geo/v1/regions' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "id": "ru-central2", "countryCode": "RU", "status": "UP" }'
  `}
</CodeBlock>

<CodeBlock language="json">
  {dedent`
    {
      "id": "geo...",
      "done": true,
      "metadata": { "@type": "type.googleapis.com/kacho.cloud.geo.v1.CreateRegionMetadata", "regionId": "ru-central2" },
      "response": { "@type": "type.googleapis.com/kacho.cloud.geo.v1.Region", "id": "ru-central2", "countryCode": "RU", "openForPlacement": true, "createdAt": "2026-06-24T10:10:00Z" }
    }
  `}
</CodeBlock>

</ApiOperation>

### Update — изменить регион (admin)

<ApiOperation method="PATCH" endpoint="/geo/v1/regions/{id}">

Меняет изменяемые поля региона — `countryCode` и `status`. Идентификатор изменить нельзя
(immutable PK), а **переименовать регион нечем**: имени у него нет, идентификатор и есть имя.
Путь маски `infra.numericInfraId` отвергается текстом неизменяемости, любой другой путь `infra.*`
— как неизвестное поле маски.

<CodeBlock language="bash">
  {dedent`
    curl -X PATCH 'http://localhost:18080/geo/v1/regions/ru-central2' \\
      -H 'Authorization: Bearer <admin-JWT>' \\
      -H 'Content-Type: application/json' \\
      -d '{ "status": "DOWN", "updateMask": "status" }'
  `}
</CodeBlock>

</ApiOperation>

### Delete — удалить регион (admin)

<ApiOperation method="DELETE" endpoint="/geo/v1/regions/{id}">

Удаляет регион. Если к региону привязана хотя бы одна [Zone](/api/zone), удаление
отвергается хранилищем (внешний ключ `ON DELETE RESTRICT`): операция приходит с
`error.code = 9` (`FAILED_PRECONDITION`) и текстом `region <id> is not empty` — сначала удаляются
зоны.

<CodeBlock language="bash">
  {dedent`
    curl -X DELETE 'http://localhost:18080/geo/v1/regions/ru-central2' \\
      -H 'Authorization: Bearer <admin-JWT>'
  `}
</CodeBlock>

</ApiOperation>

## Ошибки и граничные случаи

<table>
  <thead><tr><th>Ситуация</th><th>Код</th><th>Поведение</th></tr></thead>
  <tbody>
    <tr><td>Get несуществующего региона</td><td><code>NOT_FOUND</code></td><td><code>"Region &lt;id&gt; not found"</code> (HTTP 404)</td></tr>
    <tr><td>Update/Delete несуществующего региона</td><td><code>NOT_FOUND</code> в <code>Operation.error</code></td><td><code>"Region &lt;id&gt; not found"</code></td></tr>
    <tr><td>Create с уже занятым id</td><td><code>ALREADY_EXISTS</code> в <code>Operation.error</code></td><td><code>"Region &lt;id&gt; already exists"</code> — PK-конфликт по <code>id</code></td></tr>
    <tr><td><strong>Delete региона, к которому привязаны зоны</strong></td><td><code>FAILED_PRECONDITION</code> в <code>Operation.error</code></td><td><code>"region &lt;id&gt; is not empty"</code>: FK <code>Zone.regionId → Region.id ON DELETE RESTRICT</code>; сначала удалить зоны</td></tr>
    <tr><td>Неверная форма id или <code>countryCode</code></td><td><code>INVALID_ARGUMENT</code> (HTTP 400, синхронно)</td><td><code>"invalid region id '&lt;X&gt;'"</code>, <code>"countryCode must be an ISO-3166 alpha-2 code"</code></td></tr>
    <tr><td>Попытка изменить <code>id</code></td><td>—</td><td><code>id</code> — immutable PK; задаётся только при Create, не меняется</td></tr>
    <tr><td>Read без аутентификации</td><td><code>UNAUTHENTICATED</code></td><td>Чтение каталога грант не требует, но требует валидного принципала</td></tr>
    <tr><td>Create/Update/Delete без <code>system_admin</code></td><td><code>PERMISSION_DENIED</code> (HTTP 403)</td><td>Authz-Check не прошёл; регион не тронут</td></tr>
  </tbody>
</table>

:::warning Internal-поверхность
Полная плоскость администрирования — мутации с инфраструктурным блоком `infra` и проекция
`GetInternal` — обслуживается `InternalRegionService` на cluster-internal listener (`:9091`)
по путям `/geo/v1/internal/regions…` и **не публикуется** на external endpoint: там эти пути
отвечают `404`. Право и порог подтверждения личности у внутренних и публичных мутаций одни и те же.
:::
