# Конфигурация

Kachō Geo конфигурируется через переменные окружения с префиксом **`KACHO_GEO_`** (загрузка
через corelib `config.LoadPrefixed("KACHO_GEO")`). YAML-конфиг и ENV эквивалентны: значения
из окружения переопределяют дефолты. Эта страница перечисляет ключевые ключи и даёт пример.

:::note search_path
Схема `kacho_geo` прописывается в DSN через libpq `options=-c search_path=kacho_geo,public` — и
для pgx-пула, и для миграций. Отдельный `SET search_path` на каждый запрос не нужен.
:::

### Secure by default

Операции **без авторизации запрещены**: per-RPC authz Check (через kaname) идёт на
**обоих** listener'ах. Если адрес kaname не задан — сервис **откажется стартовать**.
Это инвариант «AuthN + AuthZ везде» (internal `:9091` не освобождён).

:::warning Обхода нет — и это построение, а не правило
Аварийной ручки, снимающей проверку прав, у сервиса **нет**. Цепочка без звена решения о
доступе носителем не выражается: `Serve` либо собрал контур, либо отказал в старте.
Источник решения — закрытое перечисление из двух значений, и третьего, означающего «не
спрашиваю никого», в нём не существует.
:::

`KACHO_GEO_AUTH_MODE` по умолчанию `production`, и в этой posture стартовать нельзя:
с plaintext-соединением к БД (`KACHO_GEO_DB_SSLMODE` пуст или `disable`), с непроверенным
транспортом любого из listener'ов или ребра к kaname, и с пустым allow-list'ом
доверенных форвардеров. `production-strict` дополнительно сужает `KACHO_GEO_DB_SSLMODE`
до {`require`, `verify-ca`, `verify-full`}.

Вне боевой posture непроверенный транспорт принимается — это нужно первой фазе начальной
установки, где стенд поднимается раньше, чем выпущены сертификаты. Прежде эту фазу
вытягивал аварийный обход, снимавший заодно и авторизацию; теперь ей не требуется снимать
ничего.

Отсюда следствие для запуска «как есть»: дефолтный `KACHO_GEO_DB_SSLMODE=disable`
несовместим с дефолтным `production` — либо задайте TLS к базе, либо выберите `dev`
явно (локальные фикстуры). Молча в dev-posture сервис не опустится.

## mTLS (per-edge)

Транспортные client/server-creds задаются **на каждое ребро отдельно** (без общего на весь
процесс TLS-синглтона). Каждая структура читает независимый набор ENV:

<table>
  <thead><tr><th>Ребро</th><th>ENV-сегмент</th><th>Назначение</th></tr></thead>
  <tbody>
    <tr><td>geo → iam (authz Check, client)</td><td><code>KACHO_GEO_IAM_AUTHZ_MTLS_&lt;NAME&gt;</code></td><td>Client-creds для дозвона в kaname (:9091)</td></tr>
    <tr><td>public listener (server)</td><td><code>KACHO_GEO_PUBLIC_SERVER_MTLS_&lt;NAME&gt;</code></td><td>Server-creds для публичного listener (:9090)</td></tr>
    <tr><td>internal listener (server)</td><td><code>KACHO_GEO_INTERNAL_SERVER_MTLS_&lt;NAME&gt;</code></td><td>Server-creds для cluster-internal listener (:9091)</td></tr>
  </tbody>
</table>

У каждой TLS-структуры есть флаг `..._ENABLE` (по умолчанию `false` — insecure back-compat для
dev). В production оба server-флага должны быть `true`.

## Пример YAML

<CodeBlock language="yaml" title="kacho-geo.yaml">
  {dedent`
    KACHO_GEO_DB_HOST: postgres.kacho.svc
    KACHO_GEO_DB_PORT: "5432"
    KACHO_GEO_DB_USER: geo
    KACHO_GEO_DB_PASSWORD: <из секрета>
    KACHO_GEO_DB_NAME: kacho_geo
    KACHO_GEO_DB_SSLMODE: verify-full

    KACHO_GEO_GRPC_PORT: "9090"
    KACHO_GEO_INTERNAL_PORT: "9091"

    KACHO_GEO_AUTH_MODE: production-strict
    KACHO_GEO_AUTHZ_IAM_GRPC_ADDR: kaname.kacho.svc:9091

    # per-edge mTLS (включить в production)
    KACHO_GEO_PUBLIC_SERVER_MTLS_ENABLE: "true"
    KACHO_GEO_INTERNAL_SERVER_MTLS_ENABLE: "true"
    KACHO_GEO_IAM_AUTHZ_MTLS_ENABLE: "true"
  `}
</CodeBlock>

:::tip Локальный dev
Для локального запуска достаточно `KACHO_GEO_DB_PASSWORD` (остальное берёт дефолты):
`KACHO_GEO_DB_PASSWORD=secret bin/kacho-geo serve`. Режим `dev` поднимет сервис без mTLS и без
kaname. Сборка и миграции — в [Быстром старте](/getting-started).
:::
