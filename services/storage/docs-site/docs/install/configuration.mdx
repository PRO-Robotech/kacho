# Конфигурация

Сервис настраивается переменными окружения с префиксом `KACHO_STORAGE_`. Ниже —
полный набор, сгруппированный по назначению.

## Слушатели

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KACHO_STORAGE_GRPC_PORT` | `9090` | Публичный листенер |
| `KACHO_STORAGE_INTERNAL_PORT` | `9091` | Внутренний листенер |
| `KACHO_STORAGE_METRICS_ADDR` | `:9095` | Диагностика и метрики |

## База данных

| Переменная | Назначение |
|---|---|
| `KACHO_STORAGE_DB_HOST` | Хост Postgres |
| `KACHO_STORAGE_DB_PORT` | Порт |
| `KACHO_STORAGE_DB_USER` | Пользователь |
| `KACHO_STORAGE_DB_PASSWORD` | Пароль — только из секрета, никогда из values |
| `KACHO_STORAGE_DB_NAME` | Имя базы (`kacho_storage`) |
| `KACHO_STORAGE_DB_SSLMODE` | Режим TLS до базы |
| `KACHO_STORAGE_DB_MAX_CONNS` | Размер пула соединений |

## Соседи

| Переменная | Куда | Зачем |
|---|---|---|
| `KACHO_STORAGE_IAM_GRPC_ADDR` | kacho-iam, публичный | Существование проекта |
| `KACHO_STORAGE_GEO_GRPC_ADDR` | kacho-geo, публичный | Существование зоны и региона, резолв «зона → регион» |
| `KACHO_STORAGE_AUTHZ_IAM_GRPC_ADDR` | kacho-iam, **внутренний** | Проверка прав на каждом запросе и регистрация владельца ресурса |

Пустой адрес означает, что клиент не подключён. Для `AUTHZ_IAM_GRPC_ADDR` это означает,
что не подключены **ни проверка прав, ни очередь регистрации владельца**, — поэтому в
production такая посадка запрещена (см. ниже).

## Безопасность

| Переменная | Назначение |
|---|---|
| `KACHO_STORAGE_AUTH_MODE` | `dev`, `production` или `production-strict` |
| `KACHO_STORAGE_PUBLIC_SERVER_MTLS_ENABLE` | mTLS на публичном листенере |
| `KACHO_STORAGE_INTERNAL_SERVER_MTLS_ENABLE` | mTLS на внутреннем листенере |
| `KACHO_STORAGE_AUTHZ_TRUSTED_FORWARDER_SANS` | Список тех, кто вправе передавать личность конечного пользователя |

:::danger Пустой список доверенных отправителей означает «не сужаем», а не «запрещаем»
`AUTHZ_TRUSTED_FORWARDER_SANS` перечисляет идентичности сертификатов, которым позволено
**говорить от имени пользователя** (передавать его личность в заголовках). Сверка со
списком выполняется, **только если список непуст**; пустой список означает, что
переданную личность примет любой проверенный по сертификату пир.

Последствие именно такое, каким кажется: сосед с сертификатом внутреннего центра
сертификации мог бы прислать заголовки личности чужого пользователя, и проверка прав
выполнилась бы **от его имени**. TLS этого не закрывает — он доказывает лишь, что пир
предъявил *какой-то* наш сертификат.

Поэтому в production проверка конфигурации при загрузке **отказывает стартовать** с
пустым списком. Список пинится по фактическим отправителям, а не по догадке «наверное,
только шлюз»: личность пользователя законно передаёт и вычислительный сервис — на пути
привязки тома.
:::

## Фильтр видимости списков

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KACHO_STORAGE_LIST_FILTER_ENABLED` | `true` | Сужение страницы по правам на каждый объект |
| `KACHO_STORAGE_LIST_FILTER_FAIL_OPEN` | `false` | Поведение при недоступности модели прав |
| `KACHO_STORAGE_LIST_FILTER_TIMEOUT_MS` | — | Бюджет времени на всю фильтрацию |
| `KACHO_STORAGE_LIST_FILTER_CACHE_TTL_MS` | — | Время жизни кэша вердиктов |
| `KACHO_STORAGE_LIST_FILTER_CACHE_MAX_ENTRIES` | — | Размер кэша вердиктов |

Бюджет времени принадлежит **запросу**, а не отдельной партии, и партии выполняются не
последовательно. Иначе на странице в 1000 записей — а это часть контракта — проверка не
уложилась бы в срок под нагрузкой и дала бы `UNAVAILABLE` на **положительном** пути.
Сужать `page_size` ради бюджета нельзя: это контракт.

`FAIL_OPEN=true` переводит фильтр в режим мягкого прохода — страница отдаётся как есть.
Каждый такой проход **наблюдаем**: пишется запись аудита. Без этого выключенный контроль
был бы невидим.

## Очередь регистрации владельца

| Переменная | Назначение |
|---|---|
| `KACHO_STORAGE_FGA_REGISTER_DRAINER_ENABLED` | Включает дренаж очереди регистрации владельца ресурса |

## Проверка конфигурации при загрузке

В режимах `production` и `production-strict` сервис **отказывается стартовать**, если
посадка небезопасна. Это не предупреждение в журнале, а отказ: процесс не поднимается.

| Условие | Сообщение отказа |
|---|---|
| Режим TLS до базы не `require` / `verify-ca` / `verify-full` | `KACHO_STORAGE_DB_SSLMODE must be one of require\|verify-ca\|verify-full` |
| Не задан адрес проверки прав | `per-RPC authz Check required on both listeners: set KACHO_STORAGE_AUTHZ_IAM_GRPC_ADDR` |
| Фильтр видимости выключен | `per-object List filter required: set KACHO_STORAGE_LIST_FILTER_ENABLED=true` |
| Фильтр в режиме мягкого прохода | `fail-closed List filter required: set KACHO_STORAGE_LIST_FILTER_FAIL_OPEN=false` |
| Пустой список доверенных отправителей | `trusted-forwarder allow-list required: set KACHO_STORAGE_AUTHZ_TRUSTED_FORWARDER_SANS` |

Сообщения отказа намеренно называют переменную и причину: без этого стенд не поднять.

:::note Почему отказ, а не предупреждение
Объявленный, но никогда не читаемый режим безопасности — это неработающая защита: сервис
поднимался бы в небезопасной посадке «в production» с одной строчкой предупреждения,
которую никто не читает. Отказ в старте делает неверную посадку **невозможной**, а не
маловероятной.

Есть и вторая сторона: проверка срабатывает только **при старте**. Если настройки
приезжают в под через `envFrom`, правка конфигурации сама по себе под не перекатывает —
процесс продолжает жить со старым окружением, и проверка не выполняется, потому что старта
не было. Поэтому шаблон пода привязан к содержимому настроек контрольной суммой: изменение
конфигурации меняет шаблон и вызывает перекат.
:::

## Дисциплина внешних вызовов

Каждый вызов соседа несёт **собственный срок**. Неотвечающий пир без срока подвесил бы
горутину навсегда, и под нагрузкой они бы копились до исчерпания процесса. Особенно это
касается проверки прав: без срока обработчик не дошёл бы до ветки закрытого отказа.

Отказ соседа на мутации — закрытый: `UNAVAILABLE`, операция не выполняется.
