# Форма идентификатора storage: слитная — и почему не мигрируем на дефисную

Решение по задаче продукта #1641. Предмет — расхождение между тем, что клиентские
страницы storage **показывали**, и тем, что платформа **чеканит**.

## Что было измерено

Клиентские страницы показывали идентификаторы дефисной формы (`vol-…`, `snp-…`,
`img-…`, `sop-…`) — **18 вхождений в 6 файлах**. Код чеканит слитную:

| ресурс | чеканка | форма |
|---|---|---|
| `Volume` | `ids.NewID(domain.PrefixVolume)` | `vol` + 17 крокфорд |
| `Snapshot` | `ids.NewID(domain.PrefixSnapshot)` | `snp` + 17 крокфорд |
| `Image` | `ids.NewID(domain.PrefixImage)` | `img` + 17 крокфорд |
| `Operation` | через `operations.New*`, префикс `domain.PrefixOperation` | `sop` + 17 крокфорд |

Проза страниц при этом была **верна**: `api/overview.mdx` объявляет «`vol` + 17
символов crockford-base32». Два места об одном предмете, и неверным было то,
которое вызывающий копирует.

## Чем это грозило вызывающему — перемерено, а не предположено

Первоначальная постановка задачи утверждала, что скопированный со страницы
идентификатор **отвергается** разбором `validate.ResourceID`, поскольку `sop` не
входит в `ids.KnownHyphenPrefixes()`. **Это неверно, и проверено исполнением:**

```
ResourceID("volume",    "vol-a1b2c3d4e5f6g7h8j") => <nil>
ResourceID("operation", "sop-a1b2c3d4e5f6g7h8j") => <nil>
```

Разбор судит **только префикс** и тело внутрь не смотрит. Дефисная ветвь для
`sop` не срабатывает, но строка проходит **legacy-ветвью** по первым трём знакам,
которые в каталоге слитных префиксов есть. Отказа о написании вызывающий не
получает **ни на одном** из пяти документированных литералов.

Что при этом верно и что делает предмет реальным: ни один из них платформа
произвести не может — все они длиной 21 знак при чеканке в 20, и **обе**
собственные проверки годности платформы их отвергают:

```
ids.IsValid(...)        => false   (для всех пяти)
ids.HasKnownPrefix(...) => false   (для всех пяти)
```

Цена клиенту, следовательно, не «внятный отказ о формате», а **круг запроса и
отказ не о том**: промах по несуществующему ресурсу либо отказ предусловия у
соседа.

## Решение: страницы приведены к слитной форме; генерация НЕ мигрируется

Из двух исходов выбран первый.

**Почему не миграция на дефисный канон.** Форма идентификатора — внешне
адресуемая координата (ban #15): она попадает в публичные URL, cross-service
ссылки и область выдачи прав, и присвоенный `id` неизменяем на всю жизнь
ресурса. Смена формы чеканки — ломающее изменение этой координаты, и в одиночку
такое не делается. Конкретно:

1. **`sop` дефисным каноном не является намеренно.** `pkg/ids` прямо оговаривает:
   per-domain префиксы операций (`sop`/`enp`/`iop`/`rop`/`aop`/`epd`) — legacy-concat,
   их маршрутизирует opsproxy по первым трём знакам. Перевод операций на дефис
   требует решения о маршрутизации края, а не правки словаря.
2. **Две формы сосуществовали бы неограниченно.** Уже созданные строки хранят
   слитные идентификаторы; миграция дала бы домен, где часть ресурсов адресуется
   одной формой, часть другой, — и различие не выводится ни из чего, кроме даты
   создания.
3. **Выигрыш не назван.** Дефисный канон заводился как *going-forward* форма для
   **новых** ресурсов редизайна (`ins-`, `mt-`, `cdg-`). У storage такого
   редизайна нет; смена формы дала бы ломающее изменение без предмета.

`vol`/`snp`/`img` при этом **уже** значатся в `ids.KnownHyphenPrefixes()` — то
есть разбор дефисную форму для них примет. Это относится к **классификации**
(что router согласен пропустить), а не к **генерации** (что владелец производит),
и второе здесь не меняется.

## Предикат возврата к вопросу

Миграция storage на дефисный канон осмысленна только вместе с редизайном домена,
который и так меняет адресацию, — тогда у ломающего изменения появляется предмет.
До тех пор форма чеканки остаётся слитной.

## Чем держится

Гейт `internal/repohygiene` `TestDocsIDFormMatchesWhatTheCodeMints`: словарь
«префикс → чеканимая форма» **выводится** из вызовов чеканки в дереве (включая
транзитивные — через посредника, куда префикс приезжает параметром), и всякий
идентификатор в клиентской странице сверяется с ним. Гейт печатает объём
осмотренного, падает на пустом обходе и доказан инъекцией в обе стороны.
