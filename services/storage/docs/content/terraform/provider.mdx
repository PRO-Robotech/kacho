# Провайдер Terraform: ресурсы хранилища

Провайдер `kacho` один на всю платформу — установка и настройка описаны на странице
«Провайдер Terraform» в документации VPC. Здесь только то, что относится к блочному
хранению.

## Ресурсы

| Ресурс | Что описывает |
|---|---|
| `kacho_storage_volume` | Том: зона, тип диска, размер, источник |
| `kacho_storage_snapshot` | Снимок тома |
| `kacho_storage_image` | Образ — региональный источник для новых томов |

Типовую связку из всех трёх описывает [модуль `storage-set`](module-storage-set).

### Источники данных

| Источник | Что читает |
|---|---|
| `kacho_storage_disk_type` · `kacho_storage_disk_types` | Запись каталога типов дисков: имя → неизменяемый идентификатор; и весь список |

Тип диска называется в томе **идентификатором**, а не именем: имя каталога косметическое и
может измениться, идентификатор — нет. Источник избавляет от того, чтобы выписывать
идентификатор в конфигурацию руками.

## Использование

```hcl
resource "kacho_storage_volume" "data" {
  project_id   = var.project_id
  zone_id      = "ru-central1-a"
  name         = "app-data"
  disk_type_id = "network-ssd"
  size_bytes   = 21474836480
}

resource "kacho_storage_snapshot" "data_daily" {
  project_id       = var.project_id
  name             = "app-data-daily"
  source_volume_id = kacho_storage_volume.data.id
}

resource "kacho_storage_image" "golden" {
  project_id         = var.project_id
  region_id          = "ru-central1"
  name               = "app-golden"
  source_snapshot_id = kacho_storage_snapshot.data_daily.id
}
```

## Что провайдер делает не так, как ожидается — и почему

### Размер обязателен у КАЖДОГО тома, включая том из снимка и из образа

Наследования размера от источника у края нет: `size_bytes` проверяется на входе всегда и
обязан быть больше нуля, иначе `Illegal argument size_bytes`. То же с `disk_type_id` — без
него отказ `volume disk_type_id is required`, синхронно, до всякой записи.

Умолчания провайдер не подставляет: том нельзя уменьшить, поэтому подставленное за вас
значение исправлялось бы только пересозданием, то есть потерей данных.

### Размер только растёт, и это проверяет край атомарно

`size_bytes` изменяем — но строго вверх. Край применяет новый размер условием
«больше текущего» прямо в записи, а не сверкой перед ней; на попытке уменьшить приходит
`Volume size can only be increased`.

`block_size` неизменяем: правка пересоздаёт том. Не задан — край подставляет `4096`.

### Источник тома — ровно один, и он неизменяем

`source_snapshot_id` и `source_image_id` взаимоисключающи (`a volume is seeded from either
a snapshot or an image, not both`). Оба помечены пересоздающими: сменить происхождение у
существующего тома нечем.

У образа источник тоже ровно один — `source_snapshot_id` либо `source_volume_id`, — но,
в отличие от тома, он **обязателен**: образ без источника край отвергает
(`Image source is required`).

### Когерентность размещения проверяется у края, и часть отказов приходит АСИНХРОННО

Существование зоны и региона край проверяет синхронно, до операции. А вот согласованность
источника с местом назначения он проверяет **внутри самой записи**, то есть уже в
асинхронной операции — `apply` дойдёт до ожидания операции и получит отказ оттуда:

| Что не сошлось | Ответ края |
|---|---|
| Том из образа, регион зоны тома ≠ регион образа | `Volume and Image must be in the same region` |
| Том из снимка, зона тома ≠ зона тома-происхождения снимка | `Volume and Snapshot must be in the same zone` |
| Том из образа, размер меньше минимума образа | `Volume size N is less than image min_disk_bytes M` |
| Тип диска не предлагается в зоне тома | `DiskType T is not offered in zone Z` |
| Тип диска не существует | `DiskType T not found` |
| Образ из источника, чья зона не входит в регион образа | `Snapshot S not found` / `Volume V not found` |

Последняя строка — не опечатка, и её стоит запомнить: **у образа несогласованное
размещение источника отвечает «не найдено»**, а не сообщением о когерентности. Так
устроено намеренно — тем же ответом край отвечает на источник из чужого проекта, и
различимый текст выдавал бы существование чужих ресурсов. У тома скрывать нечего: образ
и снимок своего проекта вызывающему уже видны, поэтому там причина называется прямо.

### Снимок и образ не несут собственной зоны

Снимок размещения не хранит вовсе: его единственное свидетельство — том, с которого он
снят. Если тот том удалён, происхождения у снимка не остаётся, и **сравнивать становится
не с чем** — тогда зональная проверка пропускает такой снимок как источник. Это не
послабление и не дефект: придумать размещение задним числом нечем.

Образ **региональный** (anycast): зоны у него нет, и том из него создаётся в любой зоне
его региона.

### Удалению мешает подключение, а происхождение — нет

| Ресурс | Что удерживает |
|---|---|
| Том | Подключение к машине — `Volume V is in use`. Сначала отсоедините |
| Снимок | Ничто |
| Образ | Ничто |

:::warning Снятие источника не отвергается — оно тихо обнуляет происхождение
Ссылки на источник объявлены `ON DELETE SET NULL`: удаляя снимок, с которого сделан
образ, вы получите **успех**, а образ останется жить с пустым источником. То же с томом
под снимком и с образом под томом.

Практическое следствие для Terraform: порядок сноса держится **графом ссылок**, а не
отказами края. В [модуле `storage-set`](module-storage-set) ссылка построена
идентификатором именно поэтому; собирая ресурсы вручную, ссылайтесь на `.id` источника,
а не на переменную с тем же значением.
:::

### Ответ «не найдено» не означает «удалено»

Общая для всех ресурсов платформы дисциплина: край отвечает на запрос к недоступному
ресурсу дословно так же, как на запрос к несуществующему, поэтому провайдер не снимает
ресурс из состояния по одному такому ответу — он подтверждает отсутствие отдельным
запросом к списку проекта и **останавливается**, если подтвердить нечем. Полная таблица
исходов — на странице «Провайдер Terraform» в документации VPC.

### Мутации асинхронны, идентификатор читается после проверки отказа

Каждое изменение возвращает операцию, и провайдер ждёт её завершения. Идентификатор
созданного ресурса он берёт из метаданных **только** после проверки, что операция не
завершилась отказом: идентификатор присутствует там и у неудачной операции, и прочитанный
без проверки указывал бы на том, которого нет.

## Поля

### `kacho_storage_volume`

| Поле | Свойство |
|---|---|
| `project_id` | обязательно, неизменяемо |
| `zone_id` | обязательно, неизменяемо; машина, к которой подключается том, обязана быть в этой же зоне |
| `name` | обязательно (см. ниже) |
| `disk_type_id` | неизменяемо; край требует его на создании |
| `size_bytes` | изменяемо только вверх |
| `block_size` | неизменяемо |
| `source_snapshot_id` · `source_image_id` | неизменяемы, взаимоисключающи |
| `description` · `labels` | изменяемы |
| `status` · `created_at` · `id` | только чтение |

### `kacho_storage_snapshot`

| Поле | Свойство |
|---|---|
| `project_id` | обязательно, неизменяемо |
| `source_volume_id` | обязательно, неизменяемо |
| `name` | обязательно |
| `description` · `labels` | изменяемы |
| `status` · `created_at` · `id` | только чтение |

### `kacho_storage_image`

| Поле | Свойство |
|---|---|
| `project_id` | обязательно, неизменяемо |
| `region_id` | обязательно, неизменяемо |
| `name` | обязательно |
| `source_snapshot_id` · `source_volume_id` | неизменяемы; ровно один обязателен |
| `description` · `labels` | изменяемы |
| `status` · `created_at` · `id` | только чтение |

### Имя обязательно, хотя платформа его не требует

`name` — единственный способ найти уже созданный ресурс, если ответ на создание не дошёл.
Без имени повтор создал бы дубль, поэтому провайдер требует имя строже, чем край.

## Импорт

```bash
tofu import kacho_storage_volume.data        vol...
tofu import kacho_storage_snapshot.data_daily snp...
tofu import kacho_storage_image.golden       img...
```

Формат проверяется по общему каталогу префиксов платформы **до** обращения к краю:
заведомо негодная строка получает внятный отказ, а не уезжает в сеть за ответом
«не найдено», который для неё ничего не значит.
