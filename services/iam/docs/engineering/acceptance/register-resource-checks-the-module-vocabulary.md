### 0.3. Замер посылок задачи — в обе стороны

Посылки #1031 перемерены **своими** командами. Одна опровергнута целиком, одна
подтверждена в суженном виде, одна оказалась устаревшей координатой.

#### Посылка 1 — ОПРОВЕРГНУТА

> «`validateTuple` проверяет ТОЛЬКО грамматику… Ни объектный тип, ни имя отношения
> ни с одним словарём не сверяются.»

Верно про `validateTuple` **как функцию** и неверно про **полосу**. До неё, на пути
запроса, стоит `validateProxyTuple` → `proxytuple.ValidateTuple`, и он сверяет
**оба**: отношение — с закрытым набором, тип объекта — с запретительным набором и
с доменом вызывающей учётки.

Опровержение получено **опытом**, а не чтением: временная проба в
`pkg/authz/proxytuple`, прогон `go test -run`, файл снят (`git status --porcelain`
пуст). Исходы:

```
system_admin @ cluster:cluster_kacho_root, caller=vpc      -> refused
system_admin @ cluster:cluster_kacho_root, caller=""       -> refused
owner        @ cluster:cluster_kacho_root, caller=vpc      -> refused
owner        @ account:acc1,               caller=vpc      -> refused
v_get (user:mod1) @ vpc_network:n1,        caller=vpc      -> refused
not_a_relation    @ vpc_network:n1,        caller=vpc      -> refused
project @ vpc_network:n1,                  caller=vpc      -> ACCEPTED
v_get (user:*) @ registry_repository:r1/x, caller=registry -> ACCEPTED
```

**Следствие для §ПРЕДМЕТ задачи.** Названная там атака — модуль пишет
`relation=system_admin, object=cluster:cluster_kacho_root` — отвергается
**сегодня**, и отвергается **двумя независимыми оговорками**: отношение вне
закрытого набора (`policy.go:231`) и тип объекта в запретительном наборе
(`policy.go:239`). Ни одна из двух не заводится этой работой. Формулировка «каждый
установленный модуль может выписать себе кластерный супер-доступ» на ревизии
`9424765ab` **ложна**, и приёмка её не воспроизводит.

#### Посылка 2 — ПОДТВЕРЖДЕНА в суженном виде, и это остаток

Тот же прогон, две строки, которые прошли:


## 1. Предмет

### 1.1. Что неверно

**У типа объекта проксируемого кортежа нет референта.** Полоса связывает тип
**приставкой** имени (`vpc` пишет `vpc_*`) и **не спрашивает**, существует ли такой
тип у платформы вообще. Выдуманный тип с законной приставкой принимается,
записывается в зеркало дословно и создаёт там строку, о типе которой не знает ни
один шаблон глаголов.

Симметрично: **связь «домен учётки → модуль каталога» выражена соглашением в Go**,
а не строкой. `objectDomainForCaller` (`policy.go:208`) возвращает имя домена как
есть, а карта исключений `moduleObjectDomain` (`policy.go:157`) **пуста**. Пока
соглашение выполняется, всё работает; сказать «этот модуль владеет вот этими
типами» данными **нечем**.

### 1.2. Почему это дефект, а не уборка

Три следствия, каждое самостоятельно достаточное.

1. **Строка зеркала с типом вне каталога невидима отовсюду.** Реконсайлер выводит
   пообъектные глаголы из шаблона типа; типа, которого нет, шаблон не знает, и
   объект получает проекцию из нуля строк. Для арендатора это выглядит как
   «регистрация прошла, доступа нет» — то есть неотличимо от честного «права нет».
   Дерево уже платило за этот класс: `#1030` завёл `role_grant_orphan` именно
   потому, что исчезновение сегмента было **тише**, чем его отказ.
2. **Опечатка модуля становится необратимой строкой чужой БД.** `resource_mirror`
   не имеет ни одного внешнего ключа (`0019_resource_mirror.sql`, три проверки, ноль
   ключей), а `object_id` — намеренно непрозрачная ссылка через границу сервиса.
   Строка с выдуманным типом не удаляется ничем, кроме административного вмешательства.
3. **Полоса — единственная запись, которую модуль делает в БД iam.** Всё
   остальное модуль получает чтением. Значит именно здесь проходит граница между
   «модуль привозит своё» и «модуль пишет в чужое».

### 1.3. Почему задача несущая для ПОРТИРУЕМОСТИ

Владелец требует: iam — **стандартный** образ; модуль привозит своё данными,
максимум сайдкар с применением. Замер по этой полосе:

| величина | значение | предикат |
|---|---:|---|
| типов ресурсов в переходнике `authzmap` | **27** | `grep -c '":' ` по блоку карты `fga_types.go` |
| из них **чужих** iam (не `iam.*`) | **20** | 9 vpc · 3 compute · 3 loadbalancer · 3 storage · 2 registry |
| чужих типов, **вкомпилированных в общий фундамент** | **1** | `publicReadObjectTypes` = `{registry_repository}` (`policy.go:128`) |
| модулей в закрытом наборе Go | **6** | `services/iam/internal/domain/module_set.go:22` |

Первые две строки — предмет `#1030`, и он **закрыт**: словарь стал строками. Третья
— предмет **этой** задачи и остаток самой узкой формы: **один** чужой тип назван
именем внутри общего фундамента, и добавление второго публично-читаемого ресурса
у нового модуля потребовало бы релиза фундамента.

Иначе говоря, задача **не** снимает выбор между «модуль неработоспособен без
релиза iam» и «модуль выписывает себе кластерные права» — этого выбора нет, вторая
половина уже закрыта (§0.3). Она снимает то, что осталось: **у приставки нет
референта, у владения — строки, у одного чужого типа — дома**.

### 1.4. ТРИ написания одного типа, которые здесь легко спутать

Это самое опасное место работы, и оно измерено, а не предположено.

| написание | пример | где живёт | предикат |
|---|---|---|---|
| **словарь модели** | `nlb_listener` | тело кортежа FGA, `relation_fact.object_type`, `resource_parent_edge.*_type` | `type_dictionaries.go`, шапка |
| **словарь каталога** | `loadbalancer.listeners` | `resource_mirror.object_type`, `role_verb.object_type`, `catalog_resource.dotted` | там же |
| **домен SAN** | `nlb` | `spiffe://kacho.cloud/ns/<ns>/sa/kacho-nlb` → `SANToServiceDomain` | `fgaproxy.go:176` |

Для балансировщика **все три различаются**, и дерево говорит это своим текстом:
`module_set.go:18` — «the load-balancer module token is `loadbalancer` (NOT `nlb`)»;
`fga_types.go:498` — `"loadbalancer.listeners": "nlb_listener"`; профиль
развёртывания даёт учётку `kacho-nlb`.

**Цена ошибки названа заранее.** Предикат, сравнивающий домен SAN с модулем
каталога напрямую, для балансировщика **не совпадёт никогда** — и не покраснеет, а
**отнимет живое право**: три типа (`nlb_listener`, `nlb_network_load_balancer`,
`nlb_target_group`) перестанут регистрироваться, а наблюдаемо это будет как
«ресурс создан, доступа нет». Тот же класс, что закрывал круг 1 приёмки `#1815`
(приведение регистра глагола), только по другой оси.

Отсюда несущее требование §2.3: **через границу словарей значение переводит
единственный переходник, и перевод стоит в ОБЕИХ полосах сравнения.**

## 2. Решение

### 2.1. Членство типа в каталоге — КЛЮЧОМ, а не условием в Go

**Норма.** Тип объекта, приведённый к словарю каталога, обязан иметь референт в
`catalog_resource(dotted, live)`. Выражается это **ключом**: `resource_mirror`
получает колонку `live boolean NOT NULL DEFAULT true` с проверкой `CHECK (live)` и
внешний ключ `(object_type, live) → catalog_resource (dotted, live)`.

**Почему ключ, а не проверка.** Запрет #10: инвариант внутри одной БД выражается
конструкцией БД. Словарь и факт лежат в **одной** схеме `kacho_iam`, значит
«прочитать, затем записать» не нужно и запрещено — под конкуренцией со снятием
типа оно даёт запись после того, как тип перестал существовать.

**Почему именно эта форма ключа.** Она landed и её образец рядом:
`role_verb_type_fk REFERENCES kacho_iam.catalog_resource (dotted, live)` плюс
`role_verb_live_true CHECK (live)`
(`20260901113757_rule_segments_have_a_referent.sql:594`, `572`). Вторая форма не
заводится: два ключа об одном предмете разошлись бы, и разошлись бы молча.

**Ключ обязан быть `DEFERRABLE INITIALLY IMMEDIATE`.** `RESTRICT` рядом с
`DEFERRABLE` принимается DDL и **молча инертен** — измерено `#1030` на PostgreSQL 16
и вынесено в гейт формы ключа (`catalog_seed_parity.go`, шапка). Новый ключ судится
тем же гейтом.

### 2.2. Принадлежность типа МОДУЛЮ вызывающей учётки — оператором

Ключ §2.1 говорит «тип существует» и **не** говорит «тип принадлежит этому
вызывающему»: личность вызывающего не является колонкой ни одной записываемой
строки, и внешним ключом это невыразимо by construction.

**Норма.** Заводится `kacho_iam.catalog_module_identity` — **три** колонки, и все
три обязательны:

| колонка | что несёт | почему не выводится |
|---|---|---|
| `module` | имя модуля в словаре каталога (`loadbalancer`) | ключ в `catalog_module(module)` |
| `san_domain` | короткое имя службы из проверенного SAN (`nlb`) | **то, что есть у полосы запроса**; для балансировщика ≠ `module` (§1.4) |
| `sa_id` | `sva`+md5 идентификатор модульной учётки | ключ в `service_accounts(id)`: строка не вправе называть несуществующую учётку |

Запись обеих проксируемых полос принимает форму
`INSERT … SELECT … WHERE EXISTS (…)`: домен вызывающего приходит **параметром
того же оператора**, а `EXISTS` соединяет `catalog_module_identity` с
`catalog_resource` по `module` в **той же транзакции**. Ноль вставленных строк —
отказ по кардинальности, ровно как у образца CAS в `data-integrity.md`.

**Почему три колонки, а не две.** Схлопывание `san_domain` в `module` отнимает
живое право у балансировщика — измерено в §1.4. Схлопывание `sa_id` оставило бы
строку без референта: identity могла бы назвать учётку, которой нет, и полоса
молча приняла бы кортеж от того, кого никто не заводил.

**Почему `san_domain` уникален.** `UNIQUE (san_domain)` — один домен принадлежит
одному модулю. Без этого два модуля могли бы объявить один домен, и «чей это тип»
перестало бы иметь ответ.

**Что это даёт портируемости.** Новый модуль привозит **строку** identity и
**строки** `catalog_resource`; ни `moduleObjectDomain`, ни закрытый набор Go
править не требуется. Прежняя карта исключений (`policy.go:157`, сегодня пустая)
перестаёт быть точкой расширения и **снимается вместе со своим предметом** — иначе
останется вторым местом об одном предмете.

### 2.3. Через границу словарей переводит ЕДИНСТВЕННЫЙ переходник, и перевод стоит с ОБЕИХ сторон

**Норма.** Значение, уезжающее в чужой словарь, переводится
`authzmap.DottedType` — и больше ничем. Второй переходник не заводится ни в SQL,
ни в Go: `type_dictionaries.go` объявляет это прямо, и настоящая работа этого
объявления не отзывает.

Практически: тип кортежа (`nlb_listener`, словарь модели) приводится к
`loadbalancer.listeners` **до** оператора, и сравнивается с `catalog_resource.dotted`
— колонкой того же словаря. Соединение колонок **разных** словарей не совпало бы
никогда и молча.

**Признак нарушения, который рецензент обязан искать:** в операторе стоит
`object_type` без приведения, либо приведение стоит **в одной** полосе из двух
(например, в положительном пути и не в отрицательном). Односторонний перевод даёт
проверку, зелёную на всём сломанном.

**Колонка с именем типа в словаре модели у `catalog_resource` НЕ заводится.**
Соблазн велик — она сделала бы оператор короче, — но это второе место, знающее
соответствие, и разойдётся оно тихо, на новом типе, которого в копии ещё нет.

### 2.4. Отношение с `catalog_verb` НЕ сверяется — и это решение, а не пропуск

Задача просит: «имя вне множества, производимого шаблоном, отвергается; `v_get`
проходит». Обещание **снимается**, и вот замер, из которого:

```sh
# что несёт каталог глаголов
sed -n '275,$p' services/iam/internal/migrations/20260901113757_rule_segments_have_a_referent.sql \
  | grep -oE "', '[a-zA-Z]+'\)" | tr -d "',)" | sort | uniq -c | sort -rn
#   27 list · 27 get · 26 update · 26 delete · 1 removetargets · 1 create · 1 addtargets
# сколько строк каталога несут отношения проксируемой полосы
for r in project parent owner v_get; do … done
#   project -> 0 · parent -> 0 · owner -> 0 · v_get -> 0
```

**109 строк каталога, ноль из проксируемых отношений.** Сверка отношения с
`catalog_verb` отвергла бы **каждую** законную проксируемую запись — то есть класс
из §1.4 в чистом виде, только с ценой в 100 % трафика полосы.

**Причина структурная, а не количественная.** `project` / `parent` / `owner` — это
**иерархия модели прав**, а не действия над ресурсом. Они объявлены в
`fga_model.fga`, принадлежат iam и модулем не привозятся: новый модуль не заводит
нового вида родства. Значит их закрытый набор — законное знание iam, портируемости
не мешает и остаётся там, где стоит (`policy.go:77`).

**И `v_get` проходит НЕ как отношение.** Измерено в §0.3: `v_get` с **именованным**
субъектом отвергается; проходит только пара `user:*` + `v_get` на типе из закрытого
списка. Формулировка задачи «`v_get` проходит» верна лишь для этой пары, и сценарий
§5.1 утверждает именно её.

### 2.5. Единственный чужой тип в общем фундаменте переезжает в каталог строкой

`publicReadObjectTypes = {"registry_repository"}` (`policy.go:128`) — **одна**
запись, и это единственное место, где имя чужого модуля вкомпилировано в общий
фундамент на этой полосе.

**Решение:** `catalog_resource` получает колонку `public_read_allowed boolean NOT
NULL DEFAULT false`; список в Go снимается, а `publicReadAllowed` спрашивает
каталог тем же оператором §2.2. Тогда «публичность — свойство контракта этого
ресурса» становится строкой, которую модуль привозит вместе со своим каталогом.

**Умолчание `false` — намеренно и это не осторожность.** Публичность расширяет
поверхность (запрет #18, ось безопасности): умолчание `true` сделало бы всякий
новый ресурс всякого модуля потенциально всемирно читаемым, и расширение было бы
**неназванным**. Сужение по субъекту (`user:*`, не именованный получатель)
остаётся неизменным — оно про то, кому нельзя выдать, а не про то, что можно
опубликовать.

**Границы решения названы честно.** `forbiddenObjectTypes` (`policy.go:142`) —
`cluster`, `account`, `project`, `user`, `service_account`, `group`, `role` — **не**
переезжает и остаётся в Go. Это типы **самого iam** и вершина иерархии; `cluster`
в каталоге ресурсов отсутствует вовсе, потому что кластер не ресурс
(`type_dictionaries.go`, шапка). Переносить в данные запрет на запись по чужому
домену значило бы сделать его отзываемым строкой — то есть ослабить границу,
которую он и держит.

### 2.6. Текст отказа НЕ меняется на проводе, различимость уезжает в журнал

Задача просит `INVALID_ARGUMENT` **с именем типа**. Производителя нет, и завести
его значило бы **отозвать** landed-решение: `proxy_tuple_refusal_transport_test.go:37`
требует дословно `"permission denied"`, а его текст падения объявляет, зачем:
названная оговорка сказала бы вызывающему, **почему** ему нельзя писать кортеж.

**Решение — то же, каким дерево уже разрешает эту напряжённость** (`handler.go:108`:
«Различимость причин отказа живёт здесь, а не в том, что видит предъявитель»):

- **на проводе** — без изменений: `PermissionDenied`, дословно `"permission denied"`,
  замок не трогается;
- **в журнале** — запись уровня предупреждения, называющая домен вызывающего,
  приведённый тип и **какая** оговорка отказала;
- **счётчиком** — отказы полосы считаются по оговорке. «Ноль отказов за всю жизнь
  контроля» обязано быть заметно, иначе мёртвый контроль невидим
  (`security.md` §Hardening, п. 8).

Производителя журнальной записи на этой полосе **сегодня нет** — измерено в §0.2
(`h.logger` в `handler.go` встречается **один** раз, и это присваивание). Он
**заводится этой работой**, и это третий из трёх законных исходов, а не умолчание.

### 2.7. Миграция проверяет СВОЙ исход и отказывает, а не догадывается

`ADD CONSTRAINT` на неполном каталоге **отбирает у арендатора живой доступ**, а
применённую миграцию править нельзя (запрет #5). Поэтому миграция, прежде чем
навесить ключ, считает и роняет применение при ненуле:

1. строки `resource_mirror`, чей `object_type` не имеет живого референта в
   `catalog_resource(dotted, live)` — включая строки **снятых** типов
   (`compute.disk`, `compute.image`, `compute.snapshot`: три записи с `live=false`,
   `20260901113757:231`);
2. строки `catalog_module_identity` без референта в `catalog_module` либо в
   `service_accounts`;
3. модули каталога **без** строки identity — иначе ключ §2.2 отвергнет их запись
   молча.

Текст отказа называет обе величины (найдено · ожидалось) и номер задачи — образец
рядом: `20260901113757:620`.

**Ненулевой счётчик по п. 1 — не повод поднять потолок.** Исходов два: перенести
строку на живой тип-преемник (`catalog_resource.superseded_by` заведён `#1030`
ровно для этого) либо снять её вместе с предметом. Ослабление ключа исходом **не**
является.

### 2.8. Что происходит с уже выданными правами — по каждому носителю

| носитель | что с ним | почему |
|---|---|---|
| кортежи в модели прав | **не трогаются** | приёмка сужает **запись**, а не отзывает записанное; отзыв — отдельный предмет с отдельной ценой |
| строки `resource_mirror` с живым типом | **не трогаются** | ключ на них сходится by construction |
| строки `resource_mirror` со снятым типом | **предмет самопроверки** §2.7, п. 1 | их число неизвестно (§0.5) и обязано быть названо до посадки |
| проекции глаголов, выведенные реконсайлером | **не трогаются** | их источник — роли, а не эта полоса |
| право `fga_writer` у модульных учёток | **не трогается** | сужается предмет записи, а не способность писать |

### 2.9. Обратного пути нет, и причина названа

Секция `+goose Down` снимает ключи и таблицу identity. Она **не восстанавливает**
строки, снятые оператором по §2.7 п. 1, — и это сказано в самой миграции, а не
подразумевается: обещание отката, которого нет, хуже отсутствия отката.

### 2.10. Впредь свойство держит ГЕЙТ, а не эта миграция

Миграция — событие; свойство держат два гейта дерева:

1. **паритет identity**: у каждого модуля закрытого набора (`domain.KnownModules()`,
   шесть имён) есть ровно одна строка identity, её `sa_id` совпадает с
   `ServiceAccountIDForService(san_domain)`, а `san_domain` соответствует учётке,
   заведённой профилем развёртывания. Расхождение здесь невидимо ничем другим:
   миграция применена и правке не подлежит, а литерал правится свободно;
2. **отсутствие второго переходника**: в дереве ровно одно объявление соответствия
   «имя модели ↔ имя каталога» (`authzmap`), и ни SQL, ни новая полоса своего не
   заводят. Гейт судит по **узлу разбора**, а не по слову: имена типов встречаются
   в комментариях, объясняющих эту же защиту, и текстовый поиск краснел бы на
   собственном объяснении.

Оба печатают объём осмотренного и падают на пустом обходе.

### 2.11. Production-complete в своих границах

Под-фаза несёт: миграцию с самопроверкой · оператор на **обеих** проксируемых
полосах (регистрация и снятие) · перенос единственного чужого литерала в каталог ·
снятие пустой карты исключений вместе с предметом · журнал и счётчик отказов ·
два гейта дерева · сценарии обеих сторон с положительными контролями. Ничего не
откладывается «на потом»; отложенное явно вынесено в §3 задачами с номерами.

### 2.12. Пять вопросов (запрет #18) — с признаком отказа у каждого

| вопрос | признак отказа | ответ |
|---|---|---|
| **благо продукта** | единственный выигрыш — меньше работы сейчас | нет: работы становится **больше** (миграция, таблица, два гейта). Выигрыш у арендатора — регистрация с выдуманным типом перестаёт молча создавать невидимый объект |
| **конкурентоспособность** | довод только «как у …» | сравнений нет. Своя ось — предсказуемость контракта: «регистрация прошла» перестаёт означать «объект может оказаться без прав» |
| **перспективность** | ошибка необратима | обратима: внешне-адресуемых координат не трогает, данных арендатора не мигрирует. Необратим лишь снос строк по §2.7 п. 1 — и он назван, сосчитан и решается человеком |
| **безопасность** | поверхность расширяется, и расширение не названо | поверхность **сужается**. Единственное расширение — колонка `public_read_allowed`, названа здесь, умолчание `false` (§2.5) |
| **производственность** | есть режим только для стенда либо часть «на потом» | нет: полоса одна на все посадки. Пустой домен вызывающего (§0.3) закрывается ключом, а не вторым режимом |

## 3. Чего эта приёмка НЕ решает

### 3.1. Отзыв уже записанных кортежей вне каталога — `#1031` не покрывает

Сужение действует **вперёд**. Кортеж, записанный до посадки на тип вне каталога,
продолжает существовать в модели прав. Предмет — сверка модели с каталогом и
отзыв разности — отдельный, и цена у него другая: он **отнимает** доступ.
**Номера у неё сегодня НЕТ, и это сказано прямо, а не обещанием.** Поиск по
трекеру (`gh issue list --state all --search 'proxytuple OR RegisterResource OR
fga_writer OR catalog'`, 60 записей) существующего предмета не нашёл: `#1032` —
про ярус роли, `#1092`/`#1027` — про порождение таблиц из манифеста, `#1827` — про
строки прав системных ролей. Значит задача заводится, и её номер — **блокирующее
предусловие** §8, п. 5, а не «сделаем потом»: обещание без номера уже блокировало
приёмку этой линии (`Б2` круга 1 приёмки `#1815`).

### 3.2. Отзыв способности `fga_writer` у неактуальных модульных учёток

Посев `0009` завёл учётки, среди которых есть `kacho-vpc-operator` — компонент,
чьи рёбра сняты решением владельца 2026-08-09 (`polyrepo.md`, врезка). Учётка и
выданное ей право заведены **применёнными миграциями** и снимаются новой. Это
другой предмет: «кто вправе писать» против «что он вправе записать», и путать их
нельзя: сужение предмета записи не отзывает способности, а отзыв способности не
сужает предмета.

**Номера тоже нет** — тем же поиском по трекеру. Заводится, и его номер — то же
блокирующее предусловие §8, п. 5.

### 3.3. Пустой домен вызывающего в dev-посадке — не находка

`fgaproxy.go:103` возвращает `("", nil)` невыверенному пиру при `prodMode=false`.
Запрет #16 объявляет dev-посадку на поднятом стенде снятой, значит производителя у
этого состояния на допускаемой продуктом посадке нет. Ключ §2.2 закрывает полосу
и там — но приёмка **не** записывает это в свои заслуги и не заводит задачу: у

## 4. Out-of-scope — явно

- **Каталог прав (`permission`/`exempt_reason`) не трогается.** Обе RPC остаются
  `<exempt>` на внутреннем слушателе: их сужает ReBAC-гейт, а не пообъектный Check,
  и настоящая работа этого не меняет.
- **`proto/` не трогается.** Ни поле, ни глагол, ни аннотация.
- **Модель прав (`fga_model.fga`) не трогается.** Ни отношения, ни типы.
- **Форма очереди намерений не трогается.** `fga_outbox` разделяется многими
  производителями (посев старта, JIT, аварийный доступ, эта полоса —
  `services/iam/internal/repo/kacho/pg/fga_outbox/emitter.go:129`), и сужение,
  положенное в общий эмитент, отвергло бы собственные выдачи iam на `account` /
  `project` / `cluster`, которых в каталоге ресурсов нет. Оператор стоит **на
  полосе прокси**, а не в общем эмитенте.
- **Реконсайлер и дренаж не трогаются.**

## 5. Сценарии

### 5.0. Какие дают RED, а какие — характеризующий замок

| вид | смысл | сколько |
|---|---|---|
| **RED** | падает на ревизии `9424765ab`, зеленеет после работы | 6 |
| **характеризующий** | зелёный **и до, и после**; закрепляет то, что работа обязана НЕ сломать | 5 |
| **формальный** | о форме артефакта, а не о поведении | 3 |

Различие названо, потому что «все зелёные после» — не доказательство: замок,
зелёный и до, ничего о работе не утверждает и обязан быть помечен как замок.

## 6. Чем держится каждое требование

| требование | держится | вид |
|---|---|---|
| тип имеет референт в каталоге | внешний ключ `(object_type, live)` | **конструкция БД** |
| снятый тип не регистрируется | тот же ключ ссылается на `(dotted, live)` | **конструкция БД** |
| тип принадлежит модулю вызывающего | `INSERT … SELECT … WHERE EXISTS` | **оператор, одна транзакция** |
| один домен — один модуль | `UNIQUE (san_domain)` | **конструкция БД** |
| identity не называет несуществующую учётку | ключ в `service_accounts(id)` | **конструкция БД** |
| identity не называет несуществующий модуль | ключ в `catalog_module(module)` | **конструкция БД** |
| каталог полон до навешивания ключа | самопроверка миграции | **оператор** |
| перевод делает один переходник | гейт по узлу разбора | **гейт дерева** |
| у каждого модуля есть identity | гейт паритета | **гейт дерева** |
| тройка эмитента принимается приёмной стороной | `internal/repohygiene/proxytupleintent_test.go` | **гейт сборки, существует** |
| текст отказа не называет оговорку | `proxy_tuple_refusal_transport_test.go` | **проба, существует** |
| «ноль отказов» заметно | счётчик по оговорке | **наблюдаемость** |

**Ни одна строка не держится вниманием.** Если рецензент найдёт такую — это
блокирующее: правило, обещающее несуществующую проверку, есть тот самый класс,
который корпус ловит.

## 7. Способность проверок УПАСТЬ — как доказывается

### 7.1. Форма доказательства

По каждой оси — **три** прогона, а не два (`testing.md` §«Гейт на класс», п. 2в):

1. **контроль** — всё цело: молчат **оба** гейта;
2. **инъекция нового** — снято **новое** свойство у элемента, чьё **старое** на
   месте: краснеет **только** новый гейт, и находка называет координату;
3. **инъекция старого** — краснеет **только** существующий гейт.

Третий прогон обязателен: без него молчание существующего контроля неотличимо от
молчания мёртвого.

### 7.2. Что обязана показать инъекция по каждой оси

| ось | инъекция | ожидаемое |
|---|---|---|
| ключ каталога | строка зеркала с выдуманным типом | отказ БД с именем ключа |
| `live` в ключе | ссылка на `(dotted)` без `live` | `IAM-MV-10` зеленеет ложно ⇒ инъекция обязана это показать |
| приведение словаря | снять `DottedType` из **одной** полосы | `IAM-MV-02` краснеет; `IAM-MV-01` молчит — и это признак, что перевод односторонний |
| identity | снять строку `loadbalancer` | `IAM-MV-02` краснеет **по имени**; `IAM-MV-01` молчит |
| паритет identity | завести седьмую строку с чужим `sa_id` | гейт §2.10 п. 1 краснеет |
| второй переходник | завести карту соответствия в SQL | гейт §2.10 п. 2 краснеет **по координате**; тот же текст **в комментарии** — молчит |

Последняя строка — обязательный законный близнец: гейт, краснеющий на собственном
объяснении, отключают первым.

### 7.3. Граница доказательства — названа, а не обойдена

Инъекция подаёт вход **сама**, синтетическим деревом. Значит она доказывает, что
механизм жив, и **не** говорит ничего о том, производится ли предмет ещё
(`testing.md` §«Гейт на класс», п. 9). Для негативного утверждения `IAM-MV-13`
(«карты исключений нет») это существенно: оно замолчит, если полосу когда-нибудь
снимут целиком. Поэтому рядом с ним стоит `IAM-MV-12`, утверждение
**положительное** — «объявление ровно одно», — а оно на исчезнувшем предмете
краснеет, а не молчит.

## 8. Предикат готовности ДО посадки

Работа не начинается, пока не выполнено **всё**:

1. **`APPROVED` от `acceptance-reviewer`.** Запрет #1; вердикт машинно читается проверкой

2. **число строк `resource_mirror` без живого референта названо** — прогоном против

3. **число строк `resource_mirror` со снятым типом названо отдельно** — они
   отличаются от п. 2 исходом: у них есть преемник;
4. **перечень модульных учёток с `fga_writer` перемерен** — включая те, что посев

5. **задачи-преемники §3.1 и §3.2 заведены, их номера стоят в §3.1 и §3.2.**
   Обещание без номера блокирует приёмку (образец: `Б2` круга 1 приёмки `#1815`).
   Ни одна из двух сегодня не существует — измерено поиском по трекеру, результат

   действие во внешнем трекере, а полоса работает без отправки на origin;
   поэтому здесь стоит названное предусловие, а не тихий пропуск.

### 13.2. Б1 (блокирующее). Производитель отказа четырёх несущих сценариев назван существующим — и произвести его НЕ МОЖЕТ

**Что стоит в приёмке.** §5.4: «`IAM-MV-05` | `PermissionDenied` + дословный текст
| `handler.go:182`, замок `:37` | **да**». То же в §5.2 («Производитель кода и
текста»), в §2.6 («на проводе — без изменений… замок не трогается») и в §6
(«текст отказа не называет оговорку | `proxy_tuple_refusal_transport_test.go` |
проба, **существует**»).

**Чем опровергнуто — четырьмя прогонами:**

1. `handler.go:180-185` — `validateProxyTuple` зовёт `proxytuple.ValidateTuple` и
   больше ничего. Функция принимает **четыре строки** и возвращает ошибку;
2. пакет **провозглашённо чист**: `git grep -nE 'database/sql|pgx|context' --
   pkg/authz/proxytuple` (без проб) → **пусто**. Он не может прочитать ни
   `catalog_resource`, ни `catalog_module_identity` — ни сегодня, ни после работы;
3. значит отказ `IAM-MV-05/06/09/10` рождается там, где приёмка его и помещает —
   в ключе §2.1 и операторе §2.2, **внутри** `h.registrar.Register(…)`. Его
   транспорт — **другой** производитель: `shared.MapRepoErr` (`handler.go:204`,
   `:226`);
4. что `MapRepoErr` из этого делает — прогнано по дереву: ветки SQLSTATE у него
   **нет** (`git grep -n '23503' -- services/iam --include='*.go'` → ни одного
   не-тестового попадания), а эмитент зеркала оборачивает **голым** `fmt.Errorf`
   (`resource_mirror/emitter.go:190`, `:327`). Несентинельная ошибка проваливается
   в хвост `errors.go:108` → **`codes.Internal "internal error"`**.

**Следствие.** Четыре из шести RED-сценариев утверждают `PermissionDenied` +
дословный текст, а дерево на спроектированной полосе произвело бы `Internal
"internal error"`. Замок `proxy_tuple_refusal_transport_test.go` этого не ловит:
он зовёт `validateProxyTuple` **напрямую** (строка 30) и новой полосы не касается
вовсе — то есть §6 объявляет держателем пробу, которая держит **соседнюю** полосу.

Это ровно тот класс, ради которого §0 и написан, и он тем опаснее, что §5.4
помечает производителя «**да**»: перепись производителей, найдя существующую
функцию с подходящим именем, засчитала её полосе, которой она не принадлежит.

**Что закрывает.** Одно из двух, и выбор — предмет приёмки, а не реализации:
(а) назвать сентинель (`iamerr.ErrPermissionDenied` с текстом ровно `permission
denied`), место обёртки и **новый** замок на полосу `MapRepoErr` — тогда §5.4
получает строку «заводится», а §6 — своего держателя; либо (б) переписать «Тогда»
четырёх сценариев под то, что производится, и назвать код честно. «Оставить как
есть» исходом не является.

### 13.3. Б2 (блокирующее). §2.5 неконструируема в названном месте и роняет гейт, который §9.1 требует зелёным

**Что стоит в приёмке.** §2.5: «список в Go снимается, а `publicReadAllowed`
спрашивает каталог **тем же оператором §2.2**».

**Чем опровергнуто.** `publicReadAllowed` — `pkg/authz/proxytuple/policy.go:198`,
зовётся из `ValidateTuple` (`policy.go:244`). Тот же прогон, что в Б1, показывает:
пакет не имеет ни `context`, ни драйвера. Сверх того — **два** независимых
следствия, каждое самостоятельно достаточное:

1. `handler.go:175` объявляет прямо: «the rule itself is transport-free **by
   design** … so a consumer's domain layer can import it without taking a
   dependency on gRPC» (`architecture.md`, правило зависимостей). Дав ему БД, мы
   отзываем landed-решение, на которое сама приёмка опирается в §2.6;
2. `internal/repohygiene/proxytupleintent_test.go:132` прогоняет тройку **каждого**
   эмитента через `ValidateTuple` **на сборке, без БД**. §9.1 требует, чтобы этот
   гейт остался зелёным, и называет его «машинным доказательством, что живого
   права не отнято». Функция, которой нужен каталог, делает его неисполнимым.

**Отдельно: у этой полосы вообще нет строки зеркала.** Публичная выдача — чистый
кортеж (`register_resource.go:224` `isPureGrant`; `IAM-MV-03` сам утверждает
«строки зеркала **не появляется**»). Значит ни ключ §2.1, ни оператор над
`resource_mirror` её не касаются **by construction**, и «тем же оператором» не
имеет референта. `IAM-MV-03` и `IAM-MV-08` остаются без производителя своего
«Тогда» после переноса.

**Что закрывает.** Назвать место, где публичность спрашивается у каталога, так,
чтобы `ValidateTuple` осталась чистой (например, полоса решает это **в
use-case**, до эмиссии кортежа, а закрытый список в общем фундаменте остаётся
вторым рубежом) — либо признать перенос §2.5 отдельным предметом с номером и снять
его из этой под-фазы. Сегодня §2.11 объявляет его частью production-complete
под-фазы, а он неконструируем.

### 13.4. Б3 (блокирующее). «Ноль строк — отказ» сталкивается с уже действующей идемпотентностью того же оператора

**Что стоит в приёмке.** §2.2: «Запись обеих проксируемых полос принимает форму
`INSERT … SELECT … WHERE EXISTS (…)` … **Ноль вставленных строк — отказ по
кардинальности**, ровно как у образца CAS в `data-integrity.md`».

**Чем опровергнуто — чтением обеих полос, которые предлагается изменить:**

- **регистрация.** `resource_mirror/emitter.go:177-186`: `ON CONFLICT … DO UPDATE
  … WHERE resource_mirror.source_version < EXCLUDED.source_version`. Комментарий
  автора того кода объявляет ноль строк **законным исходом** дословно: «или версия
  не новее (0 rows — a redelivery the monotonic guard already recognised)».
  Эмитент возвращает `Outcome{Applied: false}` — и это **успех**;
- **снятие.** `emitter.go:317-328`: `DELETE … WHERE source_version <= $3`, и
  результат **отбрасывается** (`if _, err := tx.Exec(...)`). Ноль строк —
  молчаливый успех, намеренно: контракт RPC объявляет «Idempotent: absent tuple →
  OK, never NotFound» (`handler.go:210`), а миграция `0019` — «a repeated
  RegisterResource (drainer retry) is a no-op-equivalent».

**Следствие.** Добавив `WHERE EXISTS (…каталог…)` в **эти** операторы, приёмка
делает ноль строк **двузначным**: «повторная доставка дренажа, которую сторожевая
версия правильно погасила» и «тип не в каталоге / модуль не владелец» становятся
неразличимы. Прочесть ноль как отказ — сломать идемпотентность, которую at-least-once
дренаж делает **штатным** режимом (тогда `IAM-MV-01` и `IAM-MV-04` краснеют на
повторе); прочесть как успех — сделать сужение no-op. Третьего оператор не даёт.

Ключ §2.1 этой двузначности **не имеет** и потому остаётся годным: нарушение
даёт `23503` — сигнал, отличимый от нуля строк by construction. Предмет замечания
— **только** §2.2, то есть ровно та половина, которую «внешним ключом невыразимо».

**Что закрывает.** Назвать сигнал отказа, отличимый от штатного нуля: отдельный
`SELECT … FOR SHARE` по identity **в той же транзакции** с явной кардинальностью,
либо `RAISE` из триггера, либо ключ на колонку, которую полоса всё равно пишет.
Выбор — предмет приёмки: от него зависит и код на проводе (Б1).
