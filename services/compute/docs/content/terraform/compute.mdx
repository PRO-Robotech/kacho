# Compute в Terraform

Провайдер `kacho` описывает машины декларативно. Настройка провайдера, установка и общие
особенности (асинхронность мутаций, обязательное имя, поведение при ответе «не найдено») —
на странице провайдера в документации VPC; здесь только то, что специфично для compute.

## Размер называется именем, а не идентификатором

Источник данных существует не ради удобства. Без него конфигурация обязана нести
идентификатор типа машины, а идентификаторы у разных установок **разные** — то есть
конфигурация без него непереносима по построению.

<CodeBlock language="hcl">
  {dedent`
    data "kacho_compute_machine_type" "small" {
      name = "std-v3-2"
    }

    resource "kacho_compute_instance" "app" {
      machine_type_id = data.kacho_compute_machine_type.small.id
      # ...
    }
  `}
</CodeBlock>

Источник отдаёт и размер (`vcpu`, `memory_mib`, `gpus`, `gpu_type`), и перечень зон, где тип
заказуем. Последнее годится для проверки на плане:

<CodeBlock language="hcl">
  {dedent`
    lifecycle {
      precondition {
        condition     = contains(data.kacho_compute_machine_type.small.available_zones, var.zone_id)
        error_message = "Тип машины не заказуем в этой зоне."
      }
    }
  `}
</CodeBlock>

:::note Двусмысленное имя — отказ, а не выбор за вас
Если имени отвечает больше одной записи каталога, источник данных **отказывает**. Молча
взять первую значило бы выбрать размер машины за вас, а сходство имён — ровно тот случай,
когда выбор не безразличен. На типе в состоянии `DEPRECATED` или `RETIRED` источник
предупреждает **на плане** — то есть до того, как применение упрётся в отказ.
:::

## Ключ входа — отдельный ресурс, и это видно в плане

<CodeBlock language="hcl">
  {dedent`
    resource "kacho_compute_guest_access_key" "operator" {
      project_id = var.project_id
      name       = "operator"
      public_key = var.public_key   # ТОЛЬКО публичная половина
    }

    resource "kacho_compute_instance" "app" {
      guest_access_key_ids = [kacho_compute_guest_access_key.operator.id]
      # ...
    }
  `}
</CodeBlock>

:::danger Закрытая половина не попадает в состояние Terraform
У ресурса нет и не будет атрибута с закрытым ключом. Файл состояния хранится **открытым
текстом**: закрытый ключ в нём означал бы, что доступ к файлу состояния равен доступу в
машину.
:::

:::warning Смена материала ключа пересоздаёт ресурс — и это существо, а не оформление
Другой материал — другой доступ. Подменить его на месте значило бы сменить того, кто может
войти, сохранив прежний идентификатор. Пересоздание выдаёт **новый** идентификатор, поэтому
машины, ссылающиеся на прежний, перепривязываются тем же применением — их план это покажет.

Порядок по умолчанию — «удалить, потом создать». Если разрыв доступа недопустим, заведите
второй ключ, перепривяжите машины, и только затем удалите первый.
:::

Набор ключей у машины **заменяется целиком**. Пустой список — это «снять весь доступ»,
и он отличается от «не задано»: провайдер эти два случая различает и не отправляет краю
команды, которой вы не давали.

## Группа размещения: координата одна

Вид якоря (`ZONAL` / `REGIONAL`) **выводится** из заданной координаты и доступен только на
чтение. Отдельное поле дало бы второй способ сказать то же самое, и первым же следствием
стала бы пара, описывающая размещение, которого не бывает.

<CodeBlock language="hcl">
  {dedent`
    resource "kacho_compute_placement_group" "spread" {
      project_id = var.project_id
      name       = "app-spread"
      strategy   = "SPREAD"   # либо PACK

      zone_id = var.zone_id   # ЛИБО region_id — ровно одна координата
    }
  `}
</CodeBlock>

Заданы обе координаты или ни одной — конфигурация отвергается **на плане**, а не отказом
края на применении.
