# Провайдер Terraform: ресурсы реестра

Провайдер `kacho` один на всю платформу — установка и настройка описаны на странице
«Провайдер Terraform» в документации VPC. Здесь только то, что относится к реестру.

## Ресурсы

| Ресурс | Что описывает |
|---|---|
| `kacho_registry_registry` | Реестр образов OCI: проект, регион, видимость по умолчанию |
| `kacho_registry_repository` | Репозиторий внутри реестра |

Типовую связку описывает [модуль `registry-space`](module-registry-space).

## Использование

```hcl
resource "kacho_registry_registry" "main" {
  project_id = var.project_id
  region_id  = "ru-central1"
  name       = "production"

  default_repository_visibility = "PRIVATE"
}

resource "kacho_registry_repository" "api" {
  registry_id = kacho_registry_registry.main.id
  repository  = "team/api"
  description = "образы api"
  visibility  = "PRIVATE"
}
```

## Путь загрузки строится по идентификатору, а не по имени

```
$домен/$registryId/$репозиторий:$тег
```

Имя реестра в путь **не попадает**. Это не мелочь: имя меняется свободно, и если бы путь
зависел от него, каждое переименование ломало бы всех, кто тянет образы. Идентификатор
неизменяем на всю жизнь реестра.

Домен задаётся установкой платформы, поэтому ни провайдер, ни модуль его не подставляют:
выдуманное значение выглядело бы рабочим и вело бы в никуда.

## Репозиторий адресуется парой, а не идентификатором

Своего идентификатора у репозитория нет — его адресует пара «реестр + имя». Отсюда три
следствия, которые видны в работе:

- атрибут `id` собирает провайдер как `<registryId>/<repository>`; в этом же виде
  репозиторий импортируется;
- имя может содержать косые черты (`team/service`) — край объявляет его многосегментным
  путём, и провайдер экранирует его посегментно;
- изменение имени **пересоздаёт** репозиторий.

Третье следствие — свойство **провайдера**, а не края. Переименование у края есть
(`POST …/repositories/{repository}:rename`), но провайдер им не пользуется намеренно, и
причина названа во врезке ниже.

:::danger Имя репозитория — это адрес: у реестра переименование безопасно, у репозитория нет
Имя **реестра** в путь загрузки не входит, поэтому меняется свободно. Имя **репозитория**
входит: путь `$домен/$registryId/$репозиторий:$тег` строится по нему, и другого адреса у
репозитория не существует — так устроен сам OCI, где клиент запрашивает
`/v2/<имя>/manifests/<ссылка>` по тому имени, которое назвал загружающий.

Отсюда цена, одинаковая для обоих способов сменить имя: после смены **старый путь
отвечает 404** — ни редиректа, ни алиаса. Разом становятся недействительны все `FROM` в
Dockerfile, зависимости чартов, манифесты развёртывания и ссылки конвейеров, а
обнаруживается это при следующей выкатке, обычно у чужой команды.

Различаются способы тем, что теряется **дополнительно**:

- **край, `:rename`** — переносит теги, манифесты и referrer-граф; описание, метки,
  публичность и выданные права сохраняются;
- **провайдер, пересоздание** — уничтожает теги и слои старого репозитория и заводит
  новый по умолчанию реестра.

Поэтому правку имени в конфигурации Terraform стоит считать удалением с созданием, а не
переименованием. Если менять имя всё-таки нужно, а содержимое терять нельзя — вызовите
`:rename` у края и приведите конфигурацию к новому имени вместе с состоянием
(`tofu state rm` + `tofu import`), не давая провайдеру исполнить пересоздание.
:::

```bash
tofu import kacho_registry_registry.main   reg...
tofu import kacho_registry_repository.api  reg.../team/api
```

Разделителем при импорте служит **первая** косая черта, а не последняя: иначе
`reg…/team/service` разобрался бы как реестр `reg…/team`.

:::danger Удаление репозитория снимает всё его содержимое
Теги и слои уходят вместе с ним, и отменить это нечем — копии край не держит.
:::

## Видимость по умолчанию задаётся вторым шагом

Контракт **создания** реестра поля `default_repository_visibility` не несёт — оно есть
только у изменения. Поэтому реестр с заданной видимостью провайдер заводит в два шага:
создаёт, затем донастраивает. Между шагами существует краткое окно, в котором действует
умолчание края.

Пропустить поле молча провайдер не вправе: вы его задали и вправе получить применённым.

## Видимость называется словом варианта

`PRIVATE` или `PUBLIC` — так они названы в контракте. Неизвестное значение провайдер
отвергает с перечнем допустимых, а не подставляет ноль: ноль означал бы «не задано», и
опечатка прошла бы как умолчание.

Не задано у репозитория — наследуется умолчание реестра.
