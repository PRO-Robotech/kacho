# Модуль `registry-space`

Модуль описывает реестр вместе с его репозиториями — типовую единицу, которую заводят
целиком: реестр без репозиториев пуст, а репозиторий без реестра не существует.

## Использование

```hcl
module "images" {
  source = "github.com/PRO-Robotech/kacho//terraform/modules/registry-space"

  project_id = var.project_id
  region_id  = "ru-central1"
  name       = "production"
  labels     = { origin = "terraform" }

  repositories = {
    "team/api" = { description = "образы api", visibility = "PRIVATE" }
    "team/web" = { description = "образы web" }
  }
}
```

## Переменные

| Имя | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `project_id` | `string` | — | Проект-владелец. |
| `region_id` | `string` | — | Регион реестра. Неизменяем. |
| `name` | `string` | — | Имя реестра. В путь загрузки **не** попадает. |
| `description` | `string` | `""` | Описание реестра. |
| `labels` | `map(string)` | `{}` | Метки реестра и всех репозиториев. |
| `default_repository_visibility` | `string` | `"PRIVATE"` | `PRIVATE` или `PUBLIC`. |
| `repositories` | `map(object)` | `{}` | Ключ — имя (можно с косыми чертами), значение — описание и видимость. |

### Умолчание `PRIVATE` задано явно

Публичный репозиторий разрешает анонимную загрузку. Такое решение принимают, а не получают
по невнимательности, — поэтому модуль не оставляет выбор краю, а называет его сам.

`visibility = null` у репозитория означает «наследовать умолчание реестра».

## Выходы

| Имя | Что это |
|---|---|
| `registry_id` | Идентификатор реестра — он же сегмент пути загрузки. |
| `pull_paths` | `<registryId>/<репозиторий>` по каждому ключу — **без домена и тега**. |
| `repository_visibility` | Фактическая видимость каждого репозитория. |

:::note Почему в `pull_paths` нет домена
Домен задаётся установкой платформы и модулю не известен. Подставить сюда что-нибудь
означало бы выдать значение, которое выглядит рабочим и ведёт в никуда.
:::

`repository_visibility` выведена наружу намеренно: репозиторий, унаследовавший умолчание,
отличается от заданного явно только здесь.

## Порядок сноса

Репозитории ссылаются на реестр **по идентификатору**. Ссылка строит граф зависимостей, и
`destroy` идёт в обратном порядке — репозитории раньше реестра, который их держит. Порядок
несущий: край не удаляет непустой реестр.

## Чем проверяется сам модуль

У модуля есть пробы: `tests/wiring.tftest.hcl`, гоняются командой `tofu test` из каталога
модуля. Провайдер в них подменён (`mock_provider`), то есть край не участвует — падение
означает ошибку в модуле, а не состояние стенда.

Пробы закрепляют связывание (репозиторий ссылается на реестр по идентификатору, имя с
косой чертой доезжает, видимость не подменяется) и **отвержение** негодного входа
(`VISIBILITY_PRIVATE` вместо `PRIVATE`, `private` строчными). Конвейер требует пробы от
каждого модуля и падает на модуле без них.
