# Провайдер Terraform

Провайдер `kacho` описывает ресурсы VPC декларативно: вы задаёте желаемое состояние, а он
приводит платформу к нему.

Провайдер реализует протокол плагинов v6, общий для Terraform и OpenTofu, поэтому от
конкретного исполнителя не зависит. Проверяется он **OpenTofu**; с Terraform CLI прогонов
не было — совместимость выведена из протокола, а не измерена.

## Установка

Провайдер живёт в каталоге `terraform/` репозитория продукта. Пока он не опубликован в
реестре, подключайте его локальной сборкой:

```bash
cd terraform && go build -o ~/.kacho/plugins/terraform-provider-kacho ./cmd/terraform-provider-kacho
```

```hcl
# ~/.terraformrc или ~/.tofurc
provider_installation {
  dev_overrides {
    "PRO-Robotech/kacho" = "/home/<вы>/.kacho/plugins"
  }
  direct {}
}
```

## Настройка

```hcl
terraform {
  required_providers {
    kacho = { source = "PRO-Robotech/kacho" }
  }
}

provider "kacho" {
  endpoint = "https://api.kacho.example"   # либо KACHO_ENDPOINT
  token    = var.kacho_token               # либо KACHO_TOKEN
}
```

| Атрибут | Переменная окружения | Назначение |
|---|---|---|
| `endpoint` | `KACHO_ENDPOINT` | Базовый адрес края |
| `token` | `KACHO_TOKEN` | Bearer, выпущенный IAM |
| `ca_bundle` | `KACHO_CA_BUNDLE` | PEM с корнями доверия для внутреннего центра сертификации |
| `timeout` | `KACHO_TIMEOUT` | Срок **одного** вызова, например `30s` |

:::warning Отключения проверки сертификата нет
У провайдера **нет** атрибута `insecure` или `skip_tls_verify`, и он не появится.
Непроверяемое соединение — это не настройка, а дыра, которая переживает того, кто её
включил «на пять минут». Для сертификата внутреннего центра укажите `ca_bundle`.
:::

:::note Умолчания у адреса нет намеренно
Адрес, выведенный из чужого значения, всегда непуст — провайдер выглядел бы настроенным
и обращался бы в никуда. Поэтому `endpoint` обязателен, а отказ называет оба способа его
задать.
:::

## Что провайдер делает не так, как ожидается — и почему

Три свойства платформы влияют на поведение провайдера настолько, что о них стоит знать
заранее.

### Ответ «не найдено» не означает «удалено»

Край намеренно отвечает на запрос к недоступному ресурсу **дословно так же**, как на запрос
к несуществующему: иначе по ответу можно было бы выяснять, какие ресурсы есть у соседей.

Поэтому провайдер **не удаляет ресурс из состояния по одному такому ответу**. Он проверяет
дополнительно: ищет ресурс по имени, затем запрашивает контрольную страницу проекта.

| Что наблюдается | Что делает провайдер |
|---|---|
| Ресурс найден по имени | Оставляет в состоянии: расхождения нет |
| По имени пусто, в проекте есть другие ресурсы | Снимает из состояния — удаление настоящее |
| Список отвечает отказом | **Останавливает работу**: утрачен доступ, а не ресурс |
| По имени пусто и в проекте пусто | **Останавливает работу**: различить нечем |

Последняя строка — осознанный размен. Если в проекте был ровно один ресурс и его удалили
вручную, вы получите остановку и подсказку:

```
terraform state rm <адрес ресурса>
```

Это дешевле противоположной ошибки: провайдер, который «чинит» состояние сам, при отзыве
прав предложил бы пересоздать всю инфраструктуру.

### Имя обязательно, хотя платформа его не требует

`name` — единственный способ найти уже созданный ресурс, если ответ на создание не дошёл.
Без имени повтор создал бы дубль, поэтому провайдер требует имя строже, чем край.

### Мутации асинхронны

Каждое изменение возвращает операцию, и провайдер ждёт её завершения (по умолчанию до пяти
минут). Идентификатор созданного ресурса он читает **только** после проверки, что операция
не завершилась отказом: идентификатор присутствует в метаданных даже у неудачной операции,
и прочитанный без проверки он указывал бы на несуществующий ресурс.

## Ресурсы

Домен VPC:

- [`kacho_vpc_network`](../api/network.mdx) — сеть
- [`kacho_vpc_subnet`](../api/subnet.mdx) — подсеть
- [`kacho_vpc_security_group`](../api/security-group.mdx) — группа безопасности
- [`kacho_vpc_route_table`](../api/route-table.mdx) — таблица маршрутов
- [`kacho_vpc_address`](../api/address.mdx) — адрес
- [`kacho_vpc_network_interface`](../api/network-interface.mdx) — сетевой интерфейс
- [`kacho_vpc_gateway`](../api/gateway.mdx) — шлюз выхода наружу (вид выбирается при
  создании: трансляция исходящего IPv4 либо «только исход» IPv6)
- [`kacho_vpc_cidr_group`](../api/cidr-group.mdx) — именованный набор префиксов, на который
  ссылаются правила групп безопасности вместо своей копии перечня

Все восемь описывает [модуль `vpc-network`](module-vpc-network) — там же названы свойства,
которые видны только в работе: неизменяемость вида адреса, отсутствие ветки «следующий узел
— шлюз» у маршрута, закрытая по умолчанию группа безопасности.

`AddressPool` этим провайдером не управляется: это admin-ресурс cluster-internal
поверхности, а провайдер ходит в публичный край.

### Другие домены — тот же провайдер

Провайдер один на всю платформу; ресурсы других доменов описаны в их документации:

| Домен | Ресурсы |
|---|---|
| IAM | `kacho_iam_account`, `kacho_iam_project`, `kacho_iam_group`, `kacho_iam_role`, `kacho_iam_access_binding`, `kacho_iam_service_account`, `kacho_iam_service_account_key`, `kacho_iam_user_invitation`, `kacho_iam_user_token` |
| Вычисления | `kacho_compute_instance`, `kacho_compute_guest_access_key`, `kacho_compute_placement_group` |
| Балансировщик | `kacho_nlb_target_group`, `kacho_nlb_load_balancer`, `kacho_nlb_listener` |
| Хранилище | `kacho_storage_volume`, `kacho_storage_snapshot`, `kacho_storage_image` |
| Реестр | `kacho_registry_registry`, `kacho_registry_repository` |

### Источники данных

| Источник | Что читает |
|---|---|
| `kacho_geo_region` · `kacho_geo_regions` | Регион по идентификатору и весь список регионов |
| `kacho_geo_zone` · `kacho_geo_zones` | Зону по идентификатору и весь список зон |
| `kacho_compute_machine_type` · `kacho_compute_machine_types` | Запись каталога размеров машин: имя → неизменяемый идентификатор; и список с отбором по семейству |
| `kacho_storage_disk_type` · `kacho_storage_disk_types` | Класс диска и список классов: ярус, жизненный цикл, принимает ли новые тома |
| `kacho_vpc_network_by_name` | Сеть проекта по ИМЕНИ — чтобы сослаться на уже существующую, не беря её под управление |
| `kacho_vpc_subnet_by_name` | Подсеть сети по ИМЕНИ — с той же целью |

Справочники (`geo`, каталоги размеров и классов) существуют не для удобства: без них
конфигурация обязана нести идентификаторы, а они у каждой установки свои — то есть
конфигурация без источника данных непереносима by construction. Поиск по имени решает
другую задачу: сослаться на чужой ресурс, **не импортируя** его в своё состояние.

:::note Этот перечень СВЕРЯЕТСЯ с реестром провайдера, а не поддерживается вручную
Здесь стояло, что адрес, таблица маршрутов и группа безопасности «ещё не заведены», —
при том что все три уже были в реестре. Утверждение пережило свой предмет и говорило
арендатору, что возможности нет, тогда как она была.

Теперь расхождение роняет пробу `TestDocumentedTypesMatchTheRegistry`: она сверяет имена на
этой странице с тем, что провайдер объявляет на самом деле, **в обе стороны** — и
незадокументированный тип, и задокументированный несуществующий одинаково красные.
:::

## Модули

| Модуль | Что описывает |
|---|---|
| `terraform/modules/vpc-network` | Сеть целиком: подсети, группы, таблицы, интерфейсы, адреса, шлюз |
| `terraform/modules/nlb-service` | Группа целей, балансировщик и слушатели одной единицей |
| `terraform/modules/iam-project` | Проект вместе с группами и служебными учётками |
| `terraform/modules/iam-access` | Роли одного якоря вместе с выдачами |
| `terraform/modules/iam-machine-identity` | Служебная учётка вместе с её ключами |
| `terraform/modules/storage-set` | Тома, снимки и образы одного набора |
| `terraform/modules/registry-space` | Реестр вместе с репозиториями |
