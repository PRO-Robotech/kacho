# Провайдер Terraform

Провайдер `kacho` описывает ресурсы VPC декларативно: вы задаёте желаемое состояние, а он
приводит платформу к нему. Работает и с Terraform, и с OpenTofu — протокол плагинов у них
общий.

## Установка

Провайдер живёт в каталоге `terraform/` репозитория продукта. Пока он не опубликован в
реестре, подключайте его локальной сборкой:

```bash
cd terraform && go build -o ~/.kacho/plugins/terraform-provider-kacho ./cmd/terraform-provider-kacho
```

```hcl
# ~/.terraformrc или ~/.tofurc
provider_installation {
  dev_overrides {
    "PRO-Robotech/kacho" = "/home/<вы>/.kacho/plugins"
  }
  direct {}
}
```

## Настройка

```hcl
terraform {
  required_providers {
    kacho = { source = "PRO-Robotech/kacho" }
  }
}

provider "kacho" {
  endpoint = "https://api.kacho.example"   # либо KACHO_ENDPOINT
  token    = var.kacho_token               # либо KACHO_TOKEN
}
```

| Атрибут | Переменная окружения | Назначение |
|---|---|---|
| `endpoint` | `KACHO_ENDPOINT` | Базовый адрес края |
| `token` | `KACHO_TOKEN` | Bearer, выпущенный IAM |
| `ca_bundle` | `KACHO_CA_BUNDLE` | PEM с корнями доверия для внутреннего центра сертификации |
| `timeout` | `KACHO_TIMEOUT` | Срок **одного** вызова, например `30s` |

:::warning Отключения проверки сертификата нет
У провайдера **нет** атрибута `insecure` или `skip_tls_verify`, и он не появится.
Непроверяемое соединение — это не настройка, а дыра, которая переживает того, кто её
включил «на пять минут». Для сертификата внутреннего центра укажите `ca_bundle`.
:::

:::note Умолчания у адреса нет намеренно
Адрес, выведенный из чужого значения, всегда непуст — провайдер выглядел бы настроенным
и обращался бы в никуда. Поэтому `endpoint` обязателен, а отказ называет оба способа его
задать.
:::

## Что провайдер делает не так, как ожидается — и почему

Три свойства платформы влияют на поведение провайдера настолько, что о них стоит знать
заранее.

### Ответ «не найдено» не означает «удалено»

Край намеренно отвечает на запрос к недоступному ресурсу **дословно так же**, как на запрос
к несуществующему: иначе по ответу можно было бы выяснять, какие ресурсы есть у соседей.

Поэтому провайдер **не удаляет ресурс из состояния по одному такому ответу**. Он проверяет
дополнительно: ищет ресурс по имени, затем запрашивает контрольную страницу проекта.

| Что наблюдается | Что делает провайдер |
|---|---|
| Ресурс найден по имени | Оставляет в состоянии: расхождения нет |
| По имени пусто, в проекте есть другие ресурсы | Снимает из состояния — удаление настоящее |
| Список отвечает отказом | **Останавливает работу**: утрачен доступ, а не ресурс |
| По имени пусто и в проекте пусто | **Останавливает работу**: различить нечем |

Последняя строка — осознанный размен. Если в проекте был ровно один ресурс и его удалили
вручную, вы получите остановку и подсказку:

```
terraform state rm <адрес ресурса>
```

Это дешевле противоположной ошибки: провайдер, который «чинит» состояние сам, при отзыве
прав предложил бы пересоздать всю инфраструктуру.

### Имя обязательно, хотя платформа его не требует

`name` — единственный способ найти уже созданный ресурс, если ответ на создание не дошёл.
Без имени повтор создал бы дубль, поэтому провайдер требует имя строже, чем край.

### Мутации асинхронны

Каждое изменение возвращает операцию, и провайдер ждёт её завершения (по умолчанию до пяти
минут). Идентификатор созданного ресурса он читает **только** после проверки, что операция
не завершилась отказом: идентификатор присутствует в метаданных даже у неудачной операции,
и прочитанный без проверки он указывал бы на несуществующий ресурс.

## Ресурсы

- [`kacho_vpc_subnet`](../api/subnet.mdx) — подсеть

Остальные ресурсы VPC добавляются следующими под-фазами.

## Ресурсы других доменов

Провайдер один на всю платформу, поэтому перечень выше — не весь. Домен **Compute** несёт
`kacho_compute_instance`, `kacho_compute_guest_access_key`, `kacho_compute_placement_group`
и источник данных `kacho_compute_machine_type`; их особенности описаны в документации
Compute, раздел «Terraform».

Эта строка стоит здесь не для полноты, а потому что страница провайдера — единственная,
куда приходят с вопросом «что вообще умеет провайдер». Перечень, называющий один домен и
молчащий об остальных, отвечает на него неверно.
