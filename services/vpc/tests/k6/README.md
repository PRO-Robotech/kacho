# k6 — нагрузочные тесты kacho-vpc

Pre-req:
- k6 v0.55+ (`/usr/local/bin/k6` или `~/.local/bin/k6`)
- kind-кластер с kacho-vpc запущен, port-forward `:18080`
- pre-seeded fixtures: Account/Project, Region `zone`, zones a/b/c/d,
  default AddressPool с CIDR /16+ на zone-a

## Запуск

```bash
# Single scenario
k6 run scripts/network-create-burst.js

# Прогон в CI-режиме: ПЯТЬ сценариев из девяти, по возрастанию нагрузки
# (список — в самом run-all.sh; «все» он не гоняет)
./run-all.sh

# Specific environment
k6 run --env BASE_URL=http://localhost:18080 --env PROJECT_ID=b1gXXX scripts/network-create-burst.js

# Save results
k6 run --out json=results/network-create-burst.json scripts/network-create-burst.js
```

## `resource_ops.js` — цена ПРОДУКТОВОЙ операции и доля проверки доступа

Отдельный предмет от сценариев в `scripts/`: те мерят пропускную способность
одного глагола, этот отвечает на вопрос **«сколько стоит операция целиком и
какая доля этого — проверка доступа»**. Отчёт замера —
`results/BASELINE-resource-ops.md`; ступенчатый прогонщик —
`deploy/load-tests/crud-rps-step.sh` (он же снимает процессорное время каждого
участника и счётчики проверок).

Полосы выбираются переменной `OP`:

| `OP` | что мерит |
|---|---|
| `geo_get` | **контроль**: чтение, у которого проверки прав на уровне проекта нет вовсе |
| `net_get` | чтение по id, **один и тот же** объект ⇒ вердикт из кэша |
| `net_get_cold` | то же, объект из пула (`NET_POOL_PATH`) ⇒ кэш промахивается |
| `net_list` | страница со сужением по правам (`PAGE_SIZE`) |
| `group_create` | дешёвое создание (iam: ни соседей на пути запроса, ни квоты) |
| `net_create` | дорогое создание (vpc: сага целиком синхронна) |
| `sg_create`, `subnet_create` | дополнительные формы создания |

**Горячая и холодная полосы — РАЗНЫЕ вопросы, а не два прогона одного.** Вердикт
«разрешено» кэшируется на обоих слоях (край и сервис) по 5 с, ключ включает
идентификатор объекта. Пул должен быть **больше `5 × подача`**, иначе полоса
вырождается в горячую — это видно по столбцу «проверок на операцию» в отчёте.

```bash
# пул объектов кладётся в под генератора и подаётся путём в NET_POOL_PATH
NET_POOL_PATH=/pool/net_pool.json \
  ./deploy/load-tests/crud-rps-step.sh r1 net_get_cold "25,50,100,200" 30s jwtProjectEditorA
```

Токены берутся из фикстуры (`/fixtures/fixtures.json`, ключ — `TOKEN_KEY`), её
готовит `tests/authz-fixtures/prodseed_all.py --no-patch-env`. **Ключ `--no-patch-env`
обязателен**: без него посев правит закоммиченные окружения newman, а сорванный
посев обнуляет в них `existing*`-идентификаторы.
