# stacks.txt — СОСТАВ РАЗВЁРТЫВАЕМЫХ СТЕНДОВ. Единственное место в дереве, где
# цепочка `-f` объявлена; все остальные её читают.
#
# Формат:  <имя>:<профиль>[,<профиль>…]   — профили накладываются слева направо,
# ровно как их получает helm. Строки, начинающиеся с `#`, и пустые — пропускаются.
#
# Читатели (расхождение с этим файлом больше невозможно by construction):
#   shell  — tests/helm/stacks.sh  (`--args <имя>` / `--chain <имя>` / `--names`)
#   Go     — deployStacks(t) в dbtls_declaration_test.go, оттуда все проверки
#            каталога deploy и gateway/deploy
#
# Что это чинит. Цепочку выписывали в каждой проверке отдельно, и копии
# разъехались: слой посадки боевого набора знали не все, а о среднем слое
# накладки образов две таблицы утверждали ВЗАИМОИСКЛЮЧАЮЩЕЕ — и обе были
# зелёными, потому что каждая честно проверяла то, что сама объявила. Держат
# единственность два гейта в stack_table_test.go: вторая копия цепочки — находка,
# профиль дерева, не названный ни одной цепочкой, — тоже.
#
# ── ЧТО ОБЯЗАН ЗНАТЬ ТОТ, КТО ПРАВИТ ЭТОТ ФАЙЛ ──────────────────────────────
#
# Цепочка здесь обязана совпадать с той, которой стенд поднимается НА САМОМ
# ДЕЛЕ (deploy/Makefile, helm/umbrella/cutover-fe3455.sh, шапка самого профиля).
# Профиль, объявляющий только образы, посадку НЕ объявляет и наследует её у слоя
# под собой — поэтому средний слой в такой цепочке не факультативен, и его
# пропуск читается проверками как «стенд объявил режим разработки».
#
# Слой учётных данных боевой площадки (values.fe3455-ory.yaml) в цепочке НЕ
# перечислен и перечислен быть не может: он вне git и вне машины CI. Скрипт
# раскатки добавляет его сам, поверх прочитанного отсюда.
