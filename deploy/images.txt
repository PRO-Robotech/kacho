# images.txt — ПЕРЕЧЕНЬ СОБИРАЕМЫХ СЛУЖБ И ИМЁН ИХ ОБРАЗОВ. Единственное место в
# дереве, где имя образа службы объявлено; все остальные его читают.
#
# Формат:  <служба>:<компонент профиля>:<имя образа>
#   служба          — то, что принимают `IMAGES=` и `reload-svc SVC=` (каталог
#                     службы выводится из него там же, где и раньше);
#   компонент        — ключ верхнего уровня в файлах значений умбреллы;
#   имя образа       — что собирает `docker build -t` и кладёт в узлы `kind load`.
# Строки, начинающиеся с `#`, и пустые — пропускаются.
#
# Читатели (расхождение с этим файлом больше невозможно by construction):
#   make  — deploy/Makefile: перечень SERVICES, цели build-services и reload-svc
#   Go    — TestEveryStandLocalImageHasAProducer, сверяет третье поле с тем, что
#           просит СЛОЖЕННЫЙ профиль стенда по второму, в ОБЕ стороны
#
# ── ЧТО ЭТОТ ФАЙЛ ЧИНИТ ─────────────────────────────────────────────────────
#
# Имя образа сборка НЕ ПИСАЛА, а ВЫВОДИЛА из имени службы (`kacho-$svc:dev`), тогда
# как профиль стенда называл его явно. Два объявления об одном предмете, и одно из
# них выведенное — то есть вхождений имени в дереве НОЛЬ, и перепись по строке
# находила ноль там, где расхождение уже было.
#
# Для семи служб вывод случайно совпадал с профилем. Восьмая — служба личности,
# получившая собственное имя продукта, — разошлась молча: профиль просил
# `kaname:dev`, сборка клала `kacho-iam:dev`, и отказ приходил уже в кластере
# (`pull access denied … Init:ImagePullBackOff`), через минуты после успешного
# `helm upgrade`. Ни рендер, ни `helm lint`, ни проверки посадки этого не видят.
#
# УМОЛЧАНИЯ ЗДЕСЬ НЕТ НАМЕРЕННО. Оно всегда непусто, поэтому новая служба
# читалась бы настроенной и отказывала бы в кластере — ровно тот класс, из-за
# которого этот файл заведён. Служба без строки роняет сборку, а не собирается
# под выведенным именем.
