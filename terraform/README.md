# Terraform-провайдер Kachō

Описывает ресурсы платформы декларативно. Работает и с Terraform, и с OpenTofu — протокол
плагинов у них общий.

```
terraform/
├── cmd/terraform-provider-kacho/   двоичный файл плагина
├── internal/api/                   типы контракта (ПОРОЖДЕНЫ, руками не править)
├── internal/client/                клиент края: транспорт, операции, чтение
├── internal/provider/              провайдер и ресурсы
├── modules/vpc-network/            модуль «сеть с подсетями»
├── examples/basic/                 наименьшая рабочая конфигурация (сеть и подсети)
└── examples/compute/               машина с ключом входа и правилом размещения
```

## Что провайдер покрывает

| Тип | Что это |
|---|---|
| `kacho_network` · `kacho_subnet` | сеть и подсети |
| `kacho_compute_instance` | машина |
| `kacho_compute_guest_access_key` | ключ входа гостя — **свой** срок жизни, машина ссылается на него |
| `kacho_compute_placement_group` | правило взаимного размещения: разнести (`SPREAD`) либо сблизить (`PACK`) |
| `data.kacho_compute_machine_type` | размер машины из каталога: имя → неизменяемый идентификатор |

Источник данных существует не для удобства: без него конфигурация обязана нести
идентификатор типа машины, а идентификаторы у разных установок разные — то есть
конфигурация без него непереносима by construction.

## Почему это отдельный Go-модуль

Дерево зависимостей `terraform-plugin-framework` велико. В едином модуле продукта оно вошло
бы в граф **каждого** сервиса и каждой сборки образа — выросли бы время сборки, поверхность
анализа уязвимостей и объём файла сумм. Модуль изолирован, и это свойство держит гейт
`TestProviderModuleIsIsolated` (в модуле продукта, не здесь), проверяющий шесть условий —
включая то, что корневой `go.sum` не приобрёл строк `hashicorp`.

Типы контракта приезжают **вторым выходом генерации** из общего каталога `proto/`
(`proto/buf.gen.terraform.yaml`) — только message-типы, под собственным префиксом пакета.
Поэтому провайдер не импортирует модуль продукта, а значит не нужен и `replace`.

## Сборка и локальное подключение

```bash
go build -o ~/.kacho/plugins/terraform-provider-kacho ./cmd/terraform-provider-kacho
```

```hcl
# ~/.tofurc (или ~/.terraformrc)
provider_installation {
  dev_overrides { "PRO-Robotech/kacho" = "/home/<вы>/.kacho/plugins" }
  direct {}
}
```

```bash
export KACHO_ENDPOINT=https://api.kacho.example
export KACHO_TOKEN=<токен, выпущенный IAM>
cd examples/basic && tofu apply -var project_id=<проект>
```

## Проверки

```bash
go test ./... -race        # юниты: транспорт, классификатор, операция, чтение, ресурсы
go vet ./...
golangci-lint run ./...
gosec -exclude-dir=internal/api ./...
tofu fmt -check -recursive modules examples
```

Все пять команд гоняет job `terraform-module`, и это не дублирование корневых: `./...`
**не пересекает границу модуля** — свойство инструмента, а не оплошность настройки.
Пока своих шагов у модуля не было, корневой линтер и корневой gosec видели у провайдера
ровно ноль файлов и оба честно печатали «0 находок»: «ноль найденного» было неотличимо
от «ноль прочитанного». Поэтому оба шага печатают перепись осмотренного.

> [!note] Приёмочных тестов против живого стенда НЕТ — открытый долг с предикатом
> Здесь стояло, что они «включаются переменной `TF_ACC`, а без неё пропускаются, и число
> пропущенных печатается». Ни того, ни другого в дереве нет: `TF_ACC` — **0** вхождений,
> `resource.Test(` — **0**. Утверждение пережило свой предмет и описывало защиту, которой
> не существует.
>
> Что есть на самом деле: пробы разбирают ответы края на двойнике (`httptest`) — этого
> хватает, чтобы закрепить разбор, отказы и перенос в состояние, и НЕ хватает, чтобы
> утверждать, что `apply` сходится с `plan` на живом облаке.
>
> Заводить харнесс нужно не для compute, а для провайдера целиком (ресурсы сети landed
> без него), и ему требуется поднятый стенд с посеянной топологией и токеном IAM — то
> есть тот же предмет, что у e2e. Предикат снятия этой записи: в дереве появился
> `resource.Test(` и job, который его исполняет с непустой переписью.
