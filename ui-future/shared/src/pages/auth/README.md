# Церемонии личности консоль НЕ рисует

Здесь лежали семь страниц — вход, регистрация, восстановление, выход, параметры
учётной записи, приветствие и посадка обратного перехода. Их снял #1225. Ищущему
их — куда смотреть вместо.

## Почему снято

Замер на момент снятия:

- маршрутов в дереве консоли **162**, из них монтирующих эти страницы — **0**;
  единственный `<Route>` на страницу параметров жил ВНУТРИ пробы;
- в графе импортов они выглядели достижимыми, но только через барель
  `export * from "./auth"` — ребро барреля не есть монтирование;
- те же адреса раздача отдаёт **внешнему поставщику личности**:
  `ui-future/deploy/templates/configmap-nginx.yaml`, полоса
  `^/(login|registration|recovery|verification|settings|error|consent|logout)`
  → upstream `kratosUi`.

То есть рядом лежали два способа, из которых работал один. Заготовкой под
собственного поставщика личности эти страницы не были: они говорили протоколом
внешнего — его потоки, его узлы разметки, его метки подлинности (в четырёх
тяжёлых страницах таких ссылок было 49, 46, 30 и 30). Смонтировать их значило бы
**углубить** связь с поставщиком, от которого продукт уходит.

## Действующие пути

| что нужно | куда идёт продукт |
|---|---|
| вход | `AuthContext.login` → `kratos.loginUrl` (`shared/src/contexts/AuthContext.tsx`) |
| кнопка «Войти» в оболочке | `host/src/utils/auth.ts` → тот же адрес |
| второй фактор, ключи доступа, параметры | `StepUpModal` → `kratos.settingsUrl` (`shared/src/components/molecules/auth/StepUpModal/`) |
| кодирование полей WebAuthn | `shared/src/lib/webauthn.ts` |

## Чем удержано

`shared/src/test/identity-ceremony-carriers-rendered.test.ts`: носитель, который
говорит с поставщиком по его протоколу и экспортирует компонент, обязан быть
отрендерен продуктом. Страница церемонии, заведённая здесь снова и не
смонтированная, станет находкой, а не тихо ляжет рядом.

Если решение когда-нибудь переменится и консоль **станет** вести церемонию сама,
то тем же изменением обязано сняться проксирование этих адресов: способ должен
остаться ОДИН.

## Полоса обслуживания ОБУСЛОВЛЕНА ПОСАДКОЙ — и снимается вместе с объявлениями

Полоса потоков стоит под условием `host.upstreams.kratosUi`: она есть там, где
посадка объявила адрес интерфейса поставщика, и её нет там, где не объявила.
Безусловной она быть не может в обе стороны:

- **снять её безусловно** значит снять ЕДИНСТВЕННУЮ работающую церемонию входа.
  Собственных экранов входа у консоли сегодня НЕТ НИ ОДНОГО. Перемерь одной
  командой из корня дерева — она печатает ОБА числа, всего и церемоний:

  ```sh
  find ui-future -path '*/src/pages/*' -name '*.tsx' ! -name '*.test.tsx' \
    | awk 'END{print "всего страниц:", NR}
           /\/(Login|SignIn|Registration|Register|Recovery|Verification|Consent|Logout|AccountSettings)[A-Za-z]*\.tsx$/{c++}
           END{print "из них церемоний:", c+0}'
  ```

  На `bec320cf47d` она даёт `51` и `0`. **Корень слова предикатом не годится, и
  это измерено:** прежняя редакция этой записки предлагала
  `grep -icE 'login|registr|recovery'`, и он даёт **1** — ловит `RegistryPage.tsx`
  именем другого модуля. Читатель, перемеривший дословно, получил бы единицу и
  либо объявил верное утверждение ложным, либо «починил» правильное число.
  Предикат выше проверен в обе стороны: на дереве как есть — ноль, с двумя
  подсаженными именами страниц церемоний — два;
- **вернуть её безусловно** значит обслуживать чужого поставщика и там, где его
  уже сняли.

Посадка, снявшая поставщика, обязана снять и ОБЪЯВЛЕНИЯ его браузерных адресов
(ключ `ui_url` в чартах): объявление без обслуживания выглядит работающим — неизвестный
раздаче путь достаётся общему `location /`, и тот отвечает `200` оболочкой консоли.
Держит это `deploy/tests/helm/console-serves-identity-flows-test.sh`: он судит
РЕНДЕР каждой цепочки `deploy/stacks.txt` и требует, чтобы на цепочке было либо
обслуживание, либо ноль объявлений. Чтение шаблона такого расхождения не видит
by construction — оно per-посадочное.
