# Канон консоли Kachō — регламент написания UI

Регламент написания консоли (9 микрофронтендов + `shared`, Module Federation,
React + antd + `--kc-*`-токены).

Документ ведётся **по находкам владельца**: каждое замечание к живой консоли становится
здесь нормой, чтобы класс не пришлось находить второй раз. Поэтому правила
формулируются не как «делай красиво», а как проверяемая пара: **норма** ·
**признак нарушения** · **чем держится** (тест или гейт). Правило без третьего пункта —
пожелание, а не регламент: оно переживёт то, что им обозначалось.

> [!note] Почему регламент лежит здесь, а не в `CLAUDE.md` рядом с кодом консоли
> Код ссылается на разделы несуществующего документа — `FieldLabel.tsx`
> («CLAUDE.md §4.4»), `GrantAdminModal.tsx` («kacho-ui CLAUDE.md §3.5»). Файла в дереве
> нет и **не будет**: `ui-future/.gitignore` исключает `CLAUDE.md`, `AGENTS.md` и
> `.claude/` как AI-оснастку, чей источник истины — воркспейс. Правило написания
> продукта оснасткой не является и обязано ехать вместе с кодом, поэтому его место —
> `docs/`, где оно отслеживается git.
>
> Прежняя нумерация (§3.5, §4.4) здесь **не воспроизводится**: восстановить её
> содержание неоткуда, а выдумать номер значило бы подтвердить ссылку, за которой
> ничего нет. Правила ниже нумеруются заново, от находок.

## Как проверять правку

```sh
cd ui-future/<модуль> && npm run typecheck && npm test
```

`shared` собственного прогона не имеет — его тесты исполняются модулями-workspace
(`vpc`, `iam`, `system`: их `jest.config.cjs` включает `../shared/src` в `roots`).
Правка в `shared` проверяется прогоном `vpc` (1336 проб на 2026-08-12) — не «прогоном
shared», которого не существует.

`host dashboard compute storage nlb registry` — **standalone** (свой `package-lock.json`,
корневой `npm ci` их не ставит). Локально им нужен `npm ci --prefix <пакет>`, иначе
`npm test` падает с `MODULE_NOT_FOUND` — это неустановленные зависимости, **не** красный
прогон и не дефект. В конвейере (`ui.yml`) они ставятся отдельным шагом.

## Правило 1. Форма: имя слева, ввод справа — из этой пары не выходит ничто, что в неё влезает

**Норма.** Тело формы (`ResourceFormBody`) — горизонтальная пара колонок: `labelCol`
шириной 200px несёт **имя поля и его пояснение** (`FieldLabel` = текст + ⓘ-тултип),
`wrapperCol` — **ввод**. Пользователь читает форму как две вертикали: слева перечень
того, что у ресурса есть, справа — что он вводит.

Во всю ширину выходит **только то, что в правую колонку не помещается**:
- редактор правил группы безопасности (`sg-rules`) — матрица в несколько колонок;
- `custom`-виджет — его размер знает автор поля, он и ставит `fullWidth` **явно**;
- **составной** список, чьи подполя стоят колонками (`network_interface_specs`:
  custom-секция NIC плюс вложенный список групп).

**Список сам по себе поводом не является.** Список из одного подполя — это обычное поле
с несколькими значениями (CIDR супернета, ссылка на адрес, ссылка на группу), и его
место в правой колонке.

**Признак нарушения.** Поле стоит в собственной рамке с заголовком, а левая колонка
против него пуста; имя поля названо дважды — рамкой и меткой; взгляд теряет вертикаль,
по которой шёл сверху вниз. Именно так читался супернет на `/vpc/networks/create`
(находка владельца 2026-08-12).

**Чем держится.** `ResourceFormBody.test.tsx`, describe «раскладка: имя слева, ввод
справа» — пять проб: канон для обычного поля (положительный контроль), канон для списка
из одного подполя, имя названо ровно один раз, составной список остаётся во всю ширину
(с парным положительным — иначе `null` означал бы и «не в колонке», и «поля нет»),
явный `fullWidth` сильнее вывода по типу.

**Как писать новое поле.** Ширину **не** объявляй, пока раскладка по умолчанию не
подвела: `isFullWidthField` выводит её из типа и состава подполей. `fullWidth: true`
ставится, когда виджет действительно шире правой колонки, `fullWidth: false` — когда
вывод по типу ошибся в другую сторону.

> [!warning] Предикат теста опирается на ЗАГЛУШКУ antd, а не на её классы
> В этом харнессе `antd` подменён (`shared/src/test/antd-stub.ts`): `Form.Item`
> рисуется как `<div><label>{label}</label>{дети}</div>`, классов `ant-*` не
> производится **вовсе**. Проба, проверяющая раскладку по `.ant-form-item-label`,
> зелёной не станет никогда — она утверждала бы о разметке, которой здесь нет.
> Первая редакция этой пробы была написана именно так и упала на **положительном
> контроле** (обычное скалярное поле) — контроль для того и стоял.

## Долг: `ResourceFormBody` и `FormField` форкнуты в четырёх модулях

`compute storage nlb registry` несут **свои копии** обоих файлов (импорт через `@/`,
не из `@shared`) — отставшие: без ветки `sg-rules`, со `String(cur)` вместо
`displayText`. Гейт единого источника
(`shared/src/test/shared-organisms-single-source.test.ts`) покрывает
`ResourceListPage`/`ResourceCreatePage`/`ResourceEditPage` — и **не** покрывает эти два.

Пока форки живы, правка тела формы кладётся **во все пять мест** (все четыре копии
держатся байт-идентичными — так расхождение хотя бы не растёт). Настоящее закрытие —
свести их к ре-экспорту из `@shared`, как уже сделано для `ResourceCreatePage`, и
расширить гейт. До тех пор это долг, а не устройство.
