# Кросс-модульная разработка: рабочее пространство, ловушка и порядок пина

Дерево несёт **несколько** модулей Go. Перечень **выводится**, а не выписывается —
выписанный разошёлся бы с деревом на первой же вынесенной службе, и разошёлся бы молча:

```sh
git ls-files '*go.mod'
```

Служба резолвит фундамент **опубликованной версией** (сегодня — псевдоверсией). Подмена
пути на внутренний модуль (`replace github.com/PRO-Robotech/…`) **запрещена**: при клоне
одного репозитория `replace ../` не резолвится вовсе, и сборка падает там, где её никто
не проверял.

```sh
grep -c '^replace' services/iam/go.mod   # обязан быть 0
```

## Средство: рабочее пространство Go

Локальная правка «фундамент + служба одним заходом» делается **рабочим пространством**:

```sh
cp go.work.example go.work
go list -m -f '{{.Path}} {{.Dir}}' all | grep PRO-Robotech
# оба пути указывают В ДЕРЕВО, а не в кеш модулей
```

`go.work` игнорируется git и в индекс не попадает. В индексе лежит **образец**
`go.work.example`; он называет каждый модуль дерева, и это держит гейт
`internal/repohygiene` `TestCrossModuleWorkspaceExampleNamesEveryModule` — сверка
двусторонняя, модуль без записи и запись без модуля обе находки.

## Ловушка: пространство НЕ доставляет правку

Средство даёт локальный резолв — и **только** его. Конвейер пространства не видит: он
собирает службу вызовами `go mod download -C services/iam` и `go build -C services/iam
./...`, то есть **против пина**.

| прогон | чем резолвится фундамент | что означает зелёное |
|---|---|---|
| локальный **под** `go.work` | дерево | правка согласована в дереве |
| локальный **без** пространства (`GOWORK=off`) | пин | правка доехала до службы |
| конвейер | пин | то же, на чужой машине |

Правка фундамента, от которой служба зависит, будет **зелена локально** (дерево) и
**красна в конвейере** (пин, в котором этой правки ещё нет). Оба вердикта настоящие, и
оба о разном — это тот же класс, что «локально зелено означает ровно исполненное».

**Отсюда требование.** Тронул оба модуля — прогоняй **дважды** и называй в отчёте **оба**
исхода:

```sh
go build ./... && go test ./... -short              # под go.work
GOWORK=off go build -C services/iam ./...           # как собирает конвейер
GOWORK=off go test  -C services/iam ./... -short
```

Односторонний зелёный — **неполный вердикт**, а не зелёный. Гейта на это нет и быть не
может: это свойство **прогона**, а не дерева, а гейт судит дерево. Держится вниманием, и
сказано прямо, чтобы цену знали.

## Порядок: чем правка фундамента ДОЕЗЖАЕТ до службы

Пространство ничего не доставляет. Единственный путь — **сдвиг пина**, и у него есть
предпосылка, о которую спотыкаются:

1. правка фундамента влита (либо её коммит иначе достижим с **постоянной** ссылки
   origin — временная ссылка полосы исчезает вместе с полосой, и пин осиротеет);
2. объявление модуля службы сдвигается на этот коммит:
   `go get -C services/iam github.com/PRO-Robotech/kacho@<ревизия>`;
3. `GOWORK=off go build -C services/iam ./...` — иначе проверено пространство, а не пин.

**Достижимость коммита — не формальность.** Псевдоверсия, чей коммит не достижим ни с
одной ссылки origin, перестаёт резолвиться после уборки веток, и чинить это уже нечем.
Форма выпуска и переход с псевдоверсии на опубликованную версию —
[`release-and-versioning.md`](release-and-versioning.md); здесь он не пересказывается.

## Отвергнуто

**`replace` на внутренний модуль.** Не резолвится при клоне одного репозитория —
`reading ../…/go.mod: no such file or directory`, — то есть ломает ровно ту посадку, ради
которой служба и вынесена. Запрет платформенный, не местный.

**Считать пространство заменой пину.** Оно локально by construction: конвейер его не
выкладывает, поэтому зелёное под ним не говорит о стволе ничего.
