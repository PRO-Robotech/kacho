# Форма значения перечисления читается ИЗ ОПИСАНИЯ, а не угадывается: решение

**Статус:** решение принято 2026-08-30 (задача #1622) · **Область:** публичная
поверхность края и все контракты `proto/kacho/cloud/**` · **Это ЕДИНСТВЕННОЕ
место, где выбор объявлен.** Часть решения, исполнимая без новой публичной
поверхности, уже в дереве (`gateway/internal/restmux/strict_enum.go` —
`enumViolation.String`); остальное требует APPROVED-приёмки (ban #1) и идёт
задачей-преемником.

## Предмет: обе формы написания встречаются в ОДНОМ теле запроса

Форму значения перечисления в этом дереве узнать заранее нечем. Замер
2026-08-30, предикат в конце документа:

| | перечислений |
|---|---:|
| всего | **74** |
| **все** значения несут префикс типа (`SUBJECT_TYPE_USER`) | **6** |
| **ни одно** не несёт | 1 |
| **смешанных**: нулевое значение с префиксом, остальные без | **67** |

То есть нулевое значение почти везде пишется `<ТИП>_UNSPECIFIED`, а рабочие
значения — голыми (`ZONAL`, `FIVE_TUPLE`, `PROJECT`). Шесть перечислений делают
наоборот. Клиент, создающий балансировщик, обязан написать в **одном** теле
`placement: "INTERNAL_ZONAL"` и `adminState: "ADMIN_STATE_ENABLED"` — оба поля
объявлены в одном сообщении.

**Причина названа и она одна.** `proto/buf.yaml` держит `ENUM_VALUE_PREFIX` в
списке исключений линтера. Правило, которое привело бы написания к одной форме,
выключено — значит расхождение не случайность, а следствие принятого когда-то
решения, у которого сегодня нет записи.

**Прочитать форму было неоткуда.** Машинного описания API в дереве нет ни одним
файлом (`git ls-tree -r origin/main --name-only | grep -ciE 'swagger|openapi'` →
**0**), а отказ края называл отвергнутое значение и молчал о допустимых.

## Решение

**Публикуется МАШИННОЕ ОПИСАНИЕ публичной поверхности, выведенное из
дескрипторов. Написание значений перечислений НЕ унифицируется.**

И, независимо от него и уже исполнено: **отказ по значению перечисления называет
весь словарь поля** в порядке объявления контракта. Это снимает не форму
расхождения, а его цену в тот момент, когда она возникает.

### Почему не унификация написания

Унификация — единственный способ сделать форму предсказуемой *без* описания, и
она отвергнута по цене:

| ось | замер |
|---|---:|
| перечислений, требующих переименования | **68** |
| значений, требующих переименования | **184** |

Каждое переименование — **слом провода**: тело арендатора, несущее прежнее имя,
перестаёт приниматься. Ошибка такого решения **необратима** в смысле ban #18
(«перспективность»): отзыв требует второго слома. Обратное направление — снять
префиксы у шести — дешевле по числу (6 перечислений), но ломает провод ровно так
же, и среди шести лежит `SubjectType`, которым записан субъект каждой выдачи
прав.

Отдельно: с задачи #1628 такой слом стал **громким**. Прежде край молча
отбрасывал неизвестное имя значения, и переименование проявлялось бы как «сервер
принял и сделал по-своему»; теперь оно проявится отказом. Это лучше, но не
делает слом дешевле.

### Почему описание — новая ПУБЛИЧНАЯ поверхность, а не файл в дереве

Опубликованное описание API есть **контракт**: по нему генерируют клиентов, и
разойдись оно с деревом — расхождение приезжает арендатору как рабочий код,
который не работает. Поэтому у него обязаны быть: место, гейт свежести против
дескрипторов, и решение о том, что в него **не** попадает.

## Ban #6: наивная генерация опубликовала бы административную поверхность

Это не гипотеза, а замер 2026-08-30:

| | |
|---|---:|
| служб `Internal*`, несущих `google.api.http` | **13** |
| таких аннотаций всего | **61** |
| файлов контракта, где публичная и внутренняя службы лежат ВМЕСТЕ | **1** |

Последнее число — решающее. Исключение по **именам файлов** (естественный способ
сузить вход генератора) этот случай выразить **не может**: каталог типов дисков
хранилища объявляет публичную службу чтения и административную службу правки в
одном файле. И это ровно тот случай, который рукописный перечень уже однажды
пропустил — разбор в `gateway/internal/restmux/internal_routes.go` называет его
своими словами.

**Готовый плагин наш раскол не выражает.** `protoc-gen-openapiv2` доступен
версией из `go.mod` и понимает наши REST-аннотации, но фильтра по службе у него
нет — только по входным файлам. Значит сужение обязано идти по **службе**, а не
по файлу.

**Источник истины для сужения уже существует и выведен из дескрипторов** —
`loadedHTTPBindings()` с признаком `internal` (там же). Описание обязано брать
разделение оттуда же, откуда его берёт край: два предиката об одном предмете
разошлись бы молча, и разошлись бы именно на публикации админской ручки.

## Что обязано быть верно у реализации

1. **Сужение по службе, из дескрипторов** — тем же признаком, каким край
   выбирает sub-mux. Не по именам файлов.
2. **Гейт публикации**: каждая операция описания обслуживается ПУБЛИЧНЫМ
   маршрутом края. Внутренняя операция в описании — красное с её именем.
3. **Гейт свежести**: описание, отставшее от дескрипторов, — красное. Иначе
   заводится второе место об одном предмете.
4. **Имена полей — json-форма** (`fd.JSONName()`), та, которой пишет REST-клиент
   и которую обещает каждая `api/overview.mdx`.
5. **Значения перечислений — дословно из дескриптора**, включая нулевое: оно
   принимается, и вычеркнуть его значило бы подменить факт контракта суждением.
6. **Адрес описания назван на странице**, с которой клиент начинает: описание, о
   котором негде узнать, не отличается от отсутствующего.
7. **Пустой обход — отказ**, а не пустое описание.

## Что уже исполнено, и почему это не всё

Отказ края называет допустимые значения
(`gateway/internal/restmux/strict_enum.go`, `enumViolation.String`; пробы —
`refusal_restores_next_step_test.go`). Клиент, промахнувшийся формой, узнаёт её
из отказа, а не перебором.

Это **не закрывает** #1622: узнать форму **до** первого вызова по-прежнему
неоткуда. Предикат задачи требует, чтобы три поверхности говорили одно, — а
третьей поверхности пока не существует.

## Предикаты (повторяемые)

```sh
# написание значений перечислений: всего / все с префиксом / смешанных
python3 - <<'PY'
import re,subprocess
files=[f for f in subprocess.run(['git','ls-files','proto/kacho'],
       capture_output=True,text=True).stdout.split() if f.endswith('.proto')]
scr=lambda n: re.sub(r'(?<!^)(?=[A-Z])','_',n).upper()
tot=allp=none=mix=0
for f in files:
    src=re.sub(r'//.*','',open(f).read())
    for m in re.finditer(r'\benum\s+(\w+)\s*\{(.*?)\n\s*\}', src, re.S):
        vals=re.findall(r'^\s*([A-Z][A-Z0-9_]*)\s*=', m.group(2), re.M)
        if not vals: continue
        tot+=1; p=scr(m.group(1))+'_'; n=sum(v.startswith(p) for v in vals)
        allp+=n==len(vals); none+=n==0; mix+= 0<n<len(vals)
print(tot, allp, none, mix)
PY

# служб Internal* с REST-аннотациями и файлов, где публичная лежит рядом с внутренней
grep -rl '^service Internal' proto/kacho | wc -l
for f in $(grep -rl 'google.api.http' proto/kacho --include=*.proto); do
  i=$(grep -c '^service Internal' $f); p=$(grep '^service ' $f | grep -vc Internal)
  [ "$i" -gt 0 ] && [ "$p" -gt 0 ] && echo "MIXED: $f"
done

# машинного описания в дереве нет
git ls-tree -r origin/main --name-only | grep -ciE 'swagger|openapi'
```
