# Имя снятой миграции — исторический след, а не находка

Каталог миграций сервиса сводится в одну миграцию (решение владельца: прода нет,
деструктивные операции допустимы). Сведение уничтожает **имена** отдельных миграций.
Имена рассеяны по живым документам обоих репозиториев, и проверка свежести
документации читает имя в обратных кавычках как утверждение о дереве — значит после
сведения она объявит находкой каждое такое имя разом.

Этот документ — **единственное место**, где записано, что с этим делать. Он же
называет то, чем решение держится, и предикат, по которому оно снимается.

## Замер, из которого выведено

Сведение iam: 171 миграция → 1. Числа сняты на `9b412e8569`; предикаты названы,
чтобы их можно было повторить, а не поверить.

| величина | значение | предикат |
|---|---:|---|
| миграций iam | 171 | `git ls-files 'services/iam/internal/migrations/*.sql' \| wc -l` |
| имён, уникальных для iam (у соседей таких нет) | 167 | сравнение с именами прочих каталогов миграций |
| документов ЖИВОГО корпуса, цитирующих снимаемое имя | 30 | обход корпуса проверки свежести (588 документов) |
| вхождений в них | 69 | там же |
| различных координат | 43 | там же |
| из них голым именем · полным путём | 61 · 8 | форма координаты |

Для сравнения: на том же дереве проверка свежести даёт **108** расхождений в **51**
документе. То есть сведение одного сервиса добавляет к вердикту примерно две трети
его нынешнего объёма.

## Разделение по родам — их четыре, и исход у каждого свой

**Род 1. Код и гейты, читающие каталог как данные.** Обязаны продолжать работать.
Ломает их не отсутствие файлов, а **потеря ключа**: ведомость, ключуемая номером
версии или именем файла миграции, после сведения теряет предмет по каждой записи.
Измерено исполнением: надзор за дропами iam (`services/iam/internal/migrations/dropguard.json`,
20 записей) на сведённом дереве даёт 20 находок вида «объявление пережило предмет» —
и это правильная работа гейта, а не его поломка. Той же формой ключуется базовая
линия отката схемы (`internal/repohygiene/schema-rollback-baseline.txt`).
**Перековка этих ведомостей идёт вместе со сведением**, а не отдельно: у них один
автор и один момент.

**Род 2. Пробы, названные по номеру миграции.** Их предмет — свойство схемы — остаётся;
именем становится история. Не переименовываются: переименование по номеру, которого
больше нет, ничего не приобретает и теряет прослеживаемость файла.

**Род 3. Приёмки.** Правке не подлежат — вердикт привязан к отпечатку содержимого, и
правка обесценила бы одобрение. Находок они при этом **не дают**: датированная запись
в корпус проверки свежести не входит **by construction**. Проверено обходом корпуса:
приёмок сервисов 28, из них под надзором 0. Приёмка свидетельствует о сделанном, а не
предписывает.

**Род 4. Прочая проза** — записки хранилища и инженерные страницы сервиса. Здесь и
только здесь citation живёт в живом корпусе, и она распадается надвое по **намерению**:

| намерение | пример | исход |
|---|---|---|
| **живая координата** — «где смотреть это сейчас» | «DDL обеих очередей — вот тут» | **переводится**: после сведения утверждение становится ложным само по себе, безотносительно любого инструмента |
| **исторический след** — «это сделала такая-то миграция» | «таблицу дропнули вместе с ней» | **граница**: утверждение верно и переписыванию не подлежит |

Переписывать исторический след ради тишины инструмента — подгонка документа под
инструмент. Этот ход в корпусе уже делали и уже отвергли: имя снятой ветки предписывали
писать словом, пока не завели границу.

## Надгробие — ведомость послаблений, а не архив

Границу нельзя объявить по форме имени: тогда любое выдуманное имя вида
`<номер>_<имя>.sql` проходило бы молча, и это была бы маска. Граница обязана
опираться на **факт**: имя принадлежало миграции этого сервиса и больше ей не
принадлежит. Факт этот несёт надгробие — файл рядом с миграциями, производимый
сведением. Его имя объявлено ОДНОЙ константой (`internal/repohygiene/retiredledger.go`),
потому что читателей у него два — гейт дерева и проверка свежести, — и разойтись эти
объявления могли бы только молча.

```json
{
  "service": "iam",
  "consolidated_into": "20260904000000_iam_schema_baseline.sql",
  "retired": ["0001_initial.sql", "0008_drop_organizations.sql"]
}
```

**Это не архив.** Историю несёт git, состав сведения — заголовок сводной миграции.
Надгробие существует ровно затем, чтобы послабление было **обосновано**, и потому
подчиняется правилам всякой ведомости послаблений.

**Перечисляет оно только то, что ещё цитируют** — 43 координаты, а не 171 имя.
Ведомость, записанная шире предмета, есть слепая зона, выданная вперёд.

## Почему граница не может стать маской — по построению, а не по обещанию

Проверка свежести спрашивает о покрытии **только после того, как резолв провалился**.
Пока файл миграции в дереве есть, координата резолвится, и до надгробия дело не
доходит вовсе. Значит запись, называющая живую миграцию, живую координату прикрыть
**не может** — она бессильна by construction.

Остаётся вторая половина: запись, назвавшая миграцию, которой и правда нет, но
которую больше никто не цитирует. Такая запись — послабление без предмета, и она
обязана истечь.

## Чем держится

| половина | владелец | что требует |
|---|---|---|
| запись не прикрывает живую миграцию | гейт дерева (`internal/repohygiene/retiredledger_test.go`) | имя из надгробия в каталоге отсутствует; сервис и сводная миграция названы верно |
| запись не пережила свои цитаты | проверка свежести документации | имя из надгробия называет хотя бы один живой документ |

Разделение по **владельцу**, а не по удобству: гейт дерева о цитатах в воркспейсе не
знает by construction, а проверка свежести одна видит корпус обоих репозиториев.
Способность гейта упасть и смолчать доказана инъекцией по каждой оси с законным
близнецом (`internal/repohygiene/retiredledger_injection_test.go`).

Ноль надгробий — **проход**: это состояние дерева до первого сведения и цель после
того, как цитаты уйдут. Проба, падающая на достижении своей цели, толкала бы держать
запись ради зелёного.

## Предикат снятия

Надгробие сервиса снимается целиком, когда его не цитирует ни один живой документ, —
и об этом говорит проверка свежести, а не память. До тех пор оно остаётся ровно в том
объёме, в каком у него есть предмет.

Общая нумерация версий миграций и её пространство имён — соседний предмет, он живёт в
`docs/architecture/migration-version-namespace.md` и здесь не пересказывается.
