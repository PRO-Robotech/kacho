# Возврат доступа кластерного администратора

**Статус:** принято 2026-09-06 (задача #2087, поверхность F5 приёмки
`sub-phase-KAN-WIRE-1-four-surface-producers-acceptance.md`, сценарий KAN-W5-07,
предмет ПР-7) · **Область:** служба `services/iam` · **Это ЕДИНСТВЕННОЕ место,
где процедура объявлена** — шапки функций базы на него ссылаются и своей
редакции не имеют.

## Зачем процедура объявлена ЗАРАНЕЕ

Якорь кластера — объект, на котором висит право кластерного администратора.
Ошибка вокруг него отбирает доступ **у того единственного, кто мог бы её
починить**: служба к этому моменту отвечает отказом ему же.

Базовая миграция обратного шага не имеет **by construction** — свод не
откатывается. Значит путь возврата обязан быть отдельным объявленным действием,
и объявлен он обязан быть **до** того, как понадобится: сочинять его в момент
отказа будет тот, у кого доступа уже нет.

## Признак: доступ администратора не подтверждается

```sql
-- Якорь читается ПО ФАКТУ, а не пишется литералом: процедура нужна ровно тогда,
-- когда про написание якоря неизвестно, каким оно стало.
SELECT kaname.cluster_anchor();

-- Есть ли у субъекта право кластерного администратора — тот же вопрос, который
-- задаёт продукт (`authzguard.SubjectIsClusterAdmin`): одно отношение = один факт.
SELECT EXISTS(
  SELECT 1 FROM kaname.relation_fact
   WHERE object_type = 'cluster'
     AND object_id   = kaname.cluster_anchor()
     AND relation    = 'system_admin'
     AND subject     = 'service_account:<id>');
```

Пустой ответ второго запроса при живой службе — предмет этой процедуры.

## Процедура

```sql
SELECT kaname.restore_cluster_admin('user', 'usr…');
-- либо
SELECT kaname.restore_cluster_admin('service_account', 'sva…');
```

Одна транзакция, три записи: строка выдачи `kaname.cluster_admin_grants`, строка
журнала намерений `kaname.fga_outbox`, и проекция отношения, которую из журнала
складывает триггер тем же коммитом. Повтор безопасен — второй выдачи не заводит.

Проверка после — тот же запрос признака выше; он обязан ответить `true`.

## Почему процедура идёт МИМО службы

Предпосылка отказа — «доступа нет». Всякий путь, идущий через службу, ответит
отказом ему же: путь возврата, требующий доступа, которого нет, путём возврата
не является. Поэтому процедура живёт функцией базы и требует только права писать
в эту базу.

**Прав она не добавляет, и это надо сказать прямо.** У того, кто может её
позвать, право писать в базу уже есть, то есть он и так способен сделать всё то
же самое рукой. Процедура добавляет **правильность**: якорь разрешается по
факту, а не по памяти оператора; три записи идут одной транзакцией, а не тремя
подряд; отношение кладётся **через журнал**, а не прямой вставкой в проекцию —
запись мимо журнала завела бы второй путь к одному предмету, и он разошёлся бы
молча.

## Отказы, которые процедура производит

| текст отказа | что делать |
|---|---|
| `субъект <вид>:<id> в этой базе не существует` | проверить идентификатор: возвращать доступ некому, и отношение не ответило бы никому |
| `вид субъекта <x> не поддерживается` | доступ выдаётся человеку (`user`) либо служебной учётке (`service_account`) |
| `якорь кластера не единственный: строк в kaname.clusters — N` | ограничение-синглтон снято либо не восстановлено; процедура не вправе гадать, какая из строк якорь |

## Смежное: перепись остатка и переписчик написания

Той же миграцией заведены две функции, нужные при **переходе написания** якоря
(решение W4 родительской приёмки), а не при возврате доступа:

- `kaname.cluster_anchor_residue(<написание>)` — перепись мест схемы, ещё
  несущих названное написание: текстовые колонки, jsonb, умолчания столбцов,
  предикаты ограничений. Последняя строка называет **объём осмотренного**: «ноль
  находок» обязано быть отличимо от «ноль прочитанного»;
- `kaname.rename_cluster_anchor(<старое>, <новое>)` — переписчик, одной
  транзакцией переносящий якорь по всей схеме и отчитывающийся по каждому
  тронутому месту.

Обе обходят **каталог**, а не выписанный перечень таблиц: перечень старел бы
молча вместе с каждой новой миграцией и оставил бы якорь наполовину переписанным
именно в том месте, о котором никто не подумал.

**Частичного состояния переписчик не производит by construction.** Родительский
разбор считал иначе — по посылке, что кортежи живут во внешнем хранилище прав,
куда транзакция не достаёт. Посылка больше не верна: внешний движок снят
(стадия S6 эпика #747), решение о доступе вычисляет реляционная форма в своей
базе, а проекция отношений лежит в той же транзакции. Прерывание даёт откат, то
есть «не начато», и это отличимо от завершения самим значением якоря.

## Чего этот документ НЕ объявляет

- **переход написания якоря не выполнен.** Решение W4 (`cluster_kacho_root` →
  `cluster_root`) принято родительской приёмкой; здесь построены механизмы,
  которыми он будет проведён и проверен, а сам переход идёт своим изменением;
- **процедура не заменяет посев.** Штатный путь выдачи доступа — согласователь
  старта (`seed.RunBootstrapAdmin`) по адресу почты из настроек; процедура —
  путь возврата, когда штатный уже не достижим.
